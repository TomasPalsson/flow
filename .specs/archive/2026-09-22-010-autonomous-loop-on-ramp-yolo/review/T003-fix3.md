## Fatal

W1. **The watchdog reverts the operator's edits after the CLI has exited.** negcontrol.js:75-86,
    killed at :107. `guardian.kill()` sends TERM; that TERM fires the trap's `git checkout`; the
    trap waits out its current `sleep 0.2`, so the checkout lands AFTER node has exited. `ps`
    shows the guardian alive when the CLI returns (exit 4 and exit 6).
    Receipt: CLI returns rc=4 → `printf 'MY NEW WORK' > app.txt` → one second later the file reads
    `the app`. Reverted 5/5. Silent data loss on every run.
    RULING: delete the watchdog. Run break + verifier + restore as ONE synchronous
    `spawnSync('sh', ['-c', script])` whose script installs `trap '<restore>' INT TERM EXIT`,
    truncates the target, runs the verifier, and restores. The restore completes before
    `spawnSync` returns, so nothing runs beside Node and nothing outlives the command. Ctrl-C hits
    the shell's process group, so the trap covers it. Keep the existing `try/finally` in Node as a
    second restore. Pass the target path and the verify command to the script through `env`, never
    by string interpolation — the verifier confirmed your current env-var quoting is safe; keep it.
    Acceptance: after every exit path (0, 3, 4, 5, 6, 130), no process started by the control is
    alive, and a write to the target made immediately after the CLI returns is still there two
    seconds later.

## Significant

W2. **The exit-5 message can be untrue.** A verifier holding `.git/index.lock` for 0.15s makes the
    main restore fail → rc=5 "could not restore app.txt; a human must look", file empty; 1.2s later
    the watchdog restores it. Also the two checkouts can collide on index.lock. This dissolves once
    there is only one restorer (W1). Confirm it does.
    Also: restore with a method that does not need the index lock where you can — e.g. write the
    bytes back from `git cat-file blob HEAD:<path>` or from the bytes you read before the break —
    so a verifier that holds the lock cannot turn a restorable file into a false exit 5. Your call
    on the method; state which and why.

S3 + S4. **The masking regex is replaced, not re-tuned.** Round 1 (digits only) let a mktemp path
    arm. Round 2 (alnum >= 7, digits >= 4) refuses real signals — `test_greeting` vs
    `test_emptyfile`, `TimeoutError` vs `ValueError`, `src/handlers` vs `src/parsers`, `line 1234`
    vs `5678` all refused rc=4 — and `echo "run $((RANDOM%999))"; exit 1` now ARMS (rc=0).
    RULING: measure noise instead of guessing it.
      - `cmdInit` already runs the verifier once before the gate: `verifyRun` at init.js:255. Pass
        it into `runNegControl` as `opts.baseline` (an optional field of your own module's opts —
        not a shared abstraction).
      - The control's own unbroken "before" run and `opts.baseline` ran on an identical tree.
        stable := `signatureOf(baseline.output) === signatureOf(before.output)`
      - stable     → arm iff the exit-code class OR the signature changed under the break.
      - not stable → arm iff the exit-code class changed. Output is noise; ignore it.
      - Delete `sigFor` and every custom masking regex you added. Reuse `signatureOf` unchanged.
      - When refusing because output is unstable and the exit class did not change, the one-line
        reason says so: the verifier's output differs between two runs on an unchanged tree, so
        only its exit code can be trusted, and the exit code did not change.
      - No baseline given (a direct caller) → treat as not stable. Fails closed.
    This stays within spec §5's 2 × verifyTimeout bound: the control itself still makes two runs.
    Acceptance — every one of these must hold, with a test per row:
      | verifier | expected |
      |---|---|
      | `mktemp -u; true` with --allow-green | refused, 10/10 |
      | `echo "run $((RANDOM%999))"; exit 1` | refused, 10/10 |
      | `echo $$; true` with --allow-green | refused |
      | stable text, `TimeoutError` → `ValueError` under the break, same rc | ARMS |
      | stable text, `0 tests failed` → `3 tests failed`, same rc | ARMS |
      | silent, `test -s app.txt` with --allow-green | ARMS |
