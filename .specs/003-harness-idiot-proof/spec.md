## Shared contracts (frozen — implement exactly)

C-A `lib/hookout.sh` additions (slice G1), used by later slices:
- `hook_project_dir` now returns the physical path (`cd "$d" && pwd -P`), falling back to the raw value if cd fails.
- `hook_config <key>` prints the raw value of `.claude/flow.config.json` key (via jq; "" if absent/no jq).
- `hook_ignore_patterns` prints the effective ignore list, one per line: the C4 default (`migrations/ generated/ locales/ i18n/ .generated.`) unless flow.config.json `ignore` is present (then that list wholesale), PLUS the always-on vendored list `vendor/ third_party/ site-packages/ layer/python/ .claude/skills/`.
- `hook_prune_dirs` prints the shared prune directory names, one per line: `.git node_modules .venv venv target dist build out .next .nuxt .turbo .cache coverage __pycache__ .ruff_cache .mypy_cache .pytest_cache .terraform .open-next .build .serena .skill-forge .ultracode .flow-swarm`.
- `hook_excluded_path <abs-file>` rc 0 when the file must not be judged: any path component in `hook_prune_dirs`; any `hook_ignore_patterns` substring match; a directory on its path containing `VENDORED.md`; git-ignored per `git check-ignore` — BUT the "dirty ignore file voids the exemption" rule is now turn-scoped: only when an ignore file (`.gitignore`, `.git/info/exclude`) is NEWER than the turn stamp (`hook_stamp_path`) does the exemption get skipped, and even then only for files under that ignore file's directory. `CC_HOOKS_ALL_FILES=1` → rc 1 always.
- `hook_changed_since <stamp-file>` prints absolute paths of regular files under `hook_project_dir` newer than the stamp, using `find` with `-prune` on `hook_prune_dirs` (never `-not -path`), skipping a worktree's `.git` FILE, then filtered through `hook_excluded_path`. One path per line.
- `hook_note <msg>` → prints `{"systemMessage": <json string>}` and exits 0. The user-facing, non-blocking channel. Use it wherever a hook decides NOT to block but must not be silent.
- `hook_soft <msg>` → prints `{"hookSpecificOutput":{"hookEventName":"Stop","additionalContext": <json string>}}` and exits 0. Stop-only, continues the turn without hook-error styling.
- `hook_once <key>` rc 0 the first time this key is seen in this session (state file `${TMPDIR:-/tmp}/claude-once-<session>`), rc 1 after. For "say it once per session" notes.
- `hook_count <sig>` appends sig to `${TMPDIR:-/tmp}/claude-count-<session>` and prints the count of that sig. Silent. Replaces `_lesson_nudge`: `hook_deny`/`hook_block`/`hook_feedback` no longer append ANY prose to the reason. (The stop-gate's own "/lesson" paragraph is removed by G8.)
- Existing API stays: `HOOK_INPUT hook_field have hook_stamp_path hook_deny hook_block hook_feedback hook_ok hook_off_here hook_skip_if_off hook_git_managed hook_log`. `hook_git_managed` keeps its signature but delegates the ignore logic to the turn-scoped rule above.

C-B `flow off` semantics (G2 + G10): `.claude/flow.off` silences the judging hooks EXCEPT git-guard. git-guard no longer calls `hook_skip_if_off`; it honours a separate marker `.claude/flow.unsafe` written only by `flow off --unsafe`. `flow on` removes both markers. `CC_NO_GIT_GUARD=1` disables git-guard for one session and is named in every git-guard deny message.

C-C stop-gate ↔ shared scripts (G8 + G9):
- stop-gate passes the turn's change set to test-changed via env `CC_CHANGED_FILES` (newline-separated paths relative to the project dir). When set, test-changed uses exactly that list as `changed_files` and never runs `git diff base...HEAD`.
- `test-changed --json` prints `{"status":"ran"|"no-tests"|"unavailable", "passed": true|false|null, "test_cmd":..., "test_files":[...], "changed_files":[...], "exit_code":..., "duration_ms":..., "message":...}`. `passed` is null unless status is `ran`. A runner that cannot be executed (ENOENT / exit 127) is `unavailable` with the resolved command in `message`, never `passed:false`.
- `check-all --json` ALWAYS prints one JSON object to stdout, even with no ecosystem: `{"ecosystem":null,"gates":[],"error":"no_project_file","message":"..."}` exit 0. Any crash still exits non-zero; stop-gate treats non-zero + unparsable/empty stdout as "gate could not run" (allow + `hook_note`). Under `--json` no ANSI ever reaches stdout.
- stop-gate calls `check-all --json --continue` and reads per-gate `status` ∈ `pass|fail|skipped|unavailable`; `test` gate must run even when lint/format are red.

C-D `flow next --json` (G10) keeps its shape `{next, why, state:{source,...}}` but `next` is ALWAYS a runnable command or slash command (never prose). session-context (G6) prints the `Next:` line FIRST in its block.
