# SPEC: flow — deterministic Claude Code harness in the dotfiles (rev 2, post-panel)

## Objective
After this work, `~/.dotfiles/claude/.claude/` contains a deployable, tested, Mac+Linux-portable harness layer: lifecycle hooks that enforce format/size/git-safety/done-gates deterministically and put test-weakening on the record, a `scripts/` toolbox that owns numbering, slice briefs, review packages, overlap checks and plan/skill linting, and a `harness` CLI (`bin/.local/bin/flow`) that initialises any project (tight lint thresholds, CI gate, REVIEW.md, PROGRESS.md) and diagnoses the deployment. Today none of this exists: settings.json has no hooks key, CLAUDE.md and hooks/ are not stowed, and every quality rule is prose.

**What this wave does not change:** `skills/flow/*` is out of scope, so `/flow` still computes its own spec numbering and pastes contract blocks by prose. The `scripts/` toolbox is a prerequisite for U7 (flow-v2), not a change to today's `/flow` run — apart from `skills-lint`, which is useful standing alone. Honest framing of wave 1: a deterministic safety net (hooks) plus a diagnostic (`flow doctor`), with the `/flow` experience unchanged until U7 lands.

Research basis: `docs/research/raw/harness-engineering/SYNTHESIS.md` and `research/frameworks/FRAMEWORKS-SYNTHESIS.md`; panel decisions in `scratchpad/ultracode/harness/panel/DECISIONS.md`. Agents do not need to read them; everything binding is below.

## Oracle (how every unit is judged)
- Hooks: `bash claude/.claude/hooks/tests/run.sh` — run from `~/.dotfiles`. Prints `N passed, M failed`, exit 0 only when M=0. Baseline: 1 passed (portability scan), 0 failed.
- Scripts + CLI: `bash claude/.claude/scripts/tests/run.sh` — same contract. CLI tests live in `claude/.claude/scripts/tests/test_cli.sh` and locate the CLI at `$(cd "$HERE/../../../.." && pwd -P)/bin/.local/bin/flow`.
- Shell hygiene: `shellcheck -S warning <file>` clean for every `.sh` and every extension-less bash script. run.sh runs it automatically when shellcheck is installed; it is NOT installed on this Linux box, so write shellcheck-clean code by discipline (quote every expansion, no `$?` after pipelines, `read -r`, no `local x=$(cmd)` where the exit code matters).
- Portability: every bash file passes `bash -n`, uses `#!/usr/bin/env bash`, and contains none of: `mapfile`, `readarray`, `declare -A`, `${var,,}`, `${var^^}`, `readlink -f`, `stat -c`, `stat -f`, `sed -i ` (without a temp-file pattern), `sed -r`, `grep -P`, `date -d`, `date -v`, `timeout ` (GNU-only), `realpath`, `xargs -r`, `mktemp -p`, `mktemp --tmpdir`. run.sh greps for these tokens (already implemented) and fails if found; `rtk-*.sh` are excluded from the scan as unowned legacy. A line that must use one of them inside a guarded fallback that handles both platforms carries the trailing comment `# portable-ok` and is exempt.
- A unit is DONE when: its tests pass with real output shown, the portability grep is clean, both adversaries return no Fatal/Significant findings, and shellcheck is clean **if it is installed** — it is not installed on this box, so a unit that cannot run it must say so explicitly in its report rather than claiming a clean run it never performed.

## Frozen contracts (decided here, not by agents)

### C1 — Claude Code hook protocol (from code.claude.com/docs/en/hooks, 2026-09-04)
- Hooks receive JSON on stdin. Fields used: `session_id`, `hook_event_name`, `tool_name`, `tool_input.command` (Bash), `tool_input.file_path` (Edit/Write/NotebookEdit), `stop_hook_active` (Stop), `transcript_path` (PreCompact/Stop), `trigger` (PreCompact: `manual|auto`).
- Env: `CLAUDE_PROJECT_DIR` is exported to the hook process (may be unset when run outside Claude; fall back to `$PWD`).
- Exit semantics: exit 0 = allow/continue; exit 2 on PreToolUse = block; exit 2 on PostToolUse = tool already ran, stderr is shown to Claude as feedback; exit 2 on Stop = prevent stopping, stderr shown; any other non-zero = non-blocking error shown to the user only.
- JSON stdout on exit 0: PreToolUse deny is `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"<why>"}}`. Stop block is `{"decision":"block","reason":"<why>"}`. SessionStart/UserPromptSubmit plain stdout on exit 0 is appended to Claude's context.
- Claude Code force-overrides a Stop hook after 8 consecutive blocks; a Stop hook MUST exit 0 immediately when `stop_hook_active` is `true`.

### C2 — `hooks/lib/hookout.sh` (already written by the orchestrator; source it, never modify it)

```bash
#   HOOK_INPUT            raw stdin, read once at source time
#   hook_field <jqpath>   value of a field, "" if absent/false/null (jq, python3 fallback, else "")

#   hook_block <reason>   print Stop block JSON, exit 0

#   hook_ok               exit 0

```

### C3 — Turn stamp and "changed this turn"
`hooks/turn-stamp.sh` (UserPromptSubmit) touches `$(hook_stamp_path)` and exits 0 with no stdout. `hooks/stop-gate.sh`'s "changed this turn" set is the **union** of (a) files under the project dir newer than the stamp (`find . -newer <stamp> -type f`, excluding `.git/`, `node_modules/`, `.venv/`, `target/`, `dist/`) and (b) every path reported by `git status --porcelain`. It exits 0 without running gates only when **both** are empty. The stamp is an optimisation, never the sole authority: (b) covers deletions, files written through Bash heredocs, and a stamp that has been re-touched later than the edits it was meant to precede.

### C4 — Per-project config `.claude/flow.config.json` (optional; hooks read it with jq; absent = defaults)
```json
{ "maxFileLines": 400, "maxFuncLines": 60, "stopGate": "scoped", "stopGateFullEverySec": 900,
  "sizeGuard": true, "formatOnEdit": true,
  "ignore": ["migrations/", "generated/", "locales/", "i18n/", ".generated."] }
```
`stopGate` is `"scoped"` (default when absent), `true` (full sweep every turn), or `false` (off) — see C10. `stopGateFullEverySec` is the minimum gap between full sweeps in scoped mode. `sizeGuard: false` makes `size-guard.sh` exit 0 without running, exactly as `formatOnEdit: false` does for `format-lint.sh`. `ignore` entries are path substrings skipped by size-guard and format-lint. Environment overrides for one session: `CC_MAX_FILE_LINES`, `CC_MAX_FUNC_LINES`, `CC_NO_STOP_GATE=1`, `CC_NO_SIZE_GUARD=1`. When jq is absent, treat the file as absent (defaults).

### C7 — Plan file grammar (consumed by slice-brief, slice-overlap, plan-lint; produced by the flow skill)
- File: `.claude/feature-plan.local.md`. Required top-level headings in order: `## Behavior Inventory`, one or more `## Slice <N> — <title>` (em dash U+2014 with one space either side; `N` a positive integer), `## Gate Phases`. The Behavior Inventory section contains a GitHub-flavoured markdown table whose header row is `| Behavior | Slice | Verified by |` followed by a `|---|`-style separator and at least one data row; "at least one Behavior Inventory table row" means at least one line after the separator that starts and ends with `|`.
- Each slice section, until the next `## `, contains: a bullet `- **Files**: path, path` (comma-separated, may be absent), optional `- **Depends-on**: Slice <M>[, Slice <K>]`, and three sub-headings `### Slice <N> — RED`, `### Slice <N> — GREEN`, `### Slice <N> — REFACTOR`.
- Fence-awareness is a property of the grammar, not of one script: a line inside a ``` or ~~~ fence is never a heading. `slice-brief`, `slice-overlap` and `plan-lint` must segment the file identically; U3 and U4 each carry a test asserting that a plan whose slice body contains a fenced block with a literal `## Slice 9 — decoy` line yields the same slice boundaries.
- Optional design file `.specs/<NNN>-<slug>/code-design.md` contains blocks starting `## Contract for this slice — Slice <N>` until the next `## `.

### C8 — Script CLIs (all in `claude/.claude/scripts/`, executable, `#!/usr/bin/env bash`, bash 3.2 compatible, `--help` on each, `set -u`)
- `new-spec "<title>" [--dir .specs] [--prefix flow/] [--no-branch] [--worktree] [--json]` — computes next 3-digit number from existing `<dir>/NNN-*` (collision-safe, 001 if none), slug = lowercase ASCII `[a-z0-9-]` from the title, max 40 chars, computed under `LC_ALL=C`; creates `<dir>/NNN-slug/`; unless `--no-branch`, creates and checks out branch `<prefix><slug>` from the current HEAD (if `--worktree`, instead creates `$(git rev-parse --show-toplevel)/../code-worktrees/<branch>` via `git worktree add -b`); writes `.claude/flow.json` = `{"number":"NNN","slug":"...","spec_dir":"...","branch":"...","worktree":"..."|null}`; prints the same JSON to stdout. Does not check dirtiness. Exit 1 only if not in a git repo (when a branch is requested) or the dir is not writable. Creating a **new** branch is this script's job; tests run it only inside `tmp_repo`.
- `slice-brief <plan-file> <N> [--design <code-design.md>] [--out <path>]` — extracts the `## Slice N` section (through the line before the next `## `), appends the matching `## Contract for this slice — Slice N` block from the design file when given and present, writes to `--out` (default `.claude/slices/<N>-brief.md`, dir created), prints the output path. Exit 1 if the slice heading is not found. Fence-aware per C7.
- `review-package <base> [<head>] [--out <path>]` — `head` defaults to `HEAD`; verifies both refs with `git rev-parse --verify`; writes `git log --oneline base..head`, blank line, `git diff --stat base..head`, blank line, `git diff -U10 base..head` to `--out` (default `.claude/review/<base-short>..<head-short>.diff`); prints the path and the line count. Exit 1 if a ref does not resolve. Never prints the diff to stdout.
- `slice-overlap <plan-file> [--json]` — parses every slice's `- **Files**:` list (fence-aware per C7); prints one line per file owned by 2+ slices as `<file>: Slice A, Slice B`; exit 1 if any overlap, 0 otherwise; `--json` prints `{"overlaps":[{"file":"..","slices":[..]}]}`.
- `plan-lint <plan-file>` — checks C7 grammar (fence-aware): required headings present and ordered, every slice has RED/GREEN/REFACTOR sub-headings, every `Depends-on` refers to an existing lower-numbered slice, at least one Behavior Inventory table row. Prints `OK` or one `MISSING: ...`/`INVALID: ...` line per problem; exit 1 on any problem.
- `skills-lint [<skills-dir>]` — default `$HOME/.claude/skills`; scans every `*.md` under it for path references matching `.claude/skills/<...>`, `~/.claude/<...>`, `$HOME/.claude/<...>`, and relative `references/<...>` or `scripts/<...>`; resolves each (relative ones against the containing skill's dir; `.claude/skills/...` against `$HOME` and against the skills dir's parent), and after a successful resolve also verifies the basename appears **verbatim** in a listing of its parent directory (case-insensitive APFS otherwise hides wrong-case references); ignores matches that contain `<`, `>`, `*`, or `NNN`; prints `MISSING <file>:<line> <path>` per dead reference; exit 1 if any. Also reports `TOOL <file>:<line> <cmd>` (exit code unaffected) for `command -v <cmd>` or backticked binary names in the allowlist (`better-plan`, `rtk`, `gh`, `bun`, `uv`) that are absent on this machine.

### C10 — Hook behaviors (exact)
- `session-context.sh` (SessionStart): if not in a git repo → exit 0 silently. Else print ≤ 20 lines: `## Repo state`, `branch: <name>`, `uncommitted files: <n>`, `last 3 commits:` + 3 indented lines, then `## PROGRESS.md` + first 20 lines if the file exists, then `note: REVIEW.md present` if it exists, then one line per `.claude/flow.config.json` field whose value differs from the C4 default, as `note: harness override: <key>=<value>`. Exit 0.
- `turn-stamp.sh` (UserPromptSubmit): per C3.
- `git-guard.sh` (PreToolUse/Bash): read `tool_input.command`; split compound commands on `;`, `&&`, `||`, `|`; **normalise each part first** (collapse every run of spaces/tabs to one space, trim ends) so `git  push --force` and `git<TAB>push --force` match exactly like `git push --force`; then check each part; deny (C1 JSON) when a part matches any of: `git push` with `--force` or `-f` (**allow** `--force-with-lease`); `git reset --hard`; `git clean` with `-f`; `git checkout -- .`; `git restore .` (bare only — `git restore --staged .` is not denied); `git branch -D`; `git commit` with `--no-verify` or `-n`; `rm -rf /`, `rm -rf ~`, `rm -rf $HOME`, `rm -rf .`; `chmod -R 777`. Everything else exits 0 with no output. Deny reasons name the pattern and the safe alternative. **Required test cases in U1's `test_core.sh`, each named:** `git push --force origin main` → denied; `git push --force-with-lease origin main` → allowed; `git push -f` → denied; `git commit -m "add force flag"` → allowed; `git stash && git reset --hard` → denied; `rm -rf ./dist` → allowed. **Required header comment in the shipped script:** "This is a regex blocklist over a command string. It raises the bar against an ordinary mistake; it is not a security boundary — `bash -c`, `eval`, variable construction, and a helper script written via Edit all evade it. CI is the real backstop."
- `format-lint.sh` (PostToolUse/Edit|Write|NotebookEdit): read `tool_input.file_path`; exit 0 if missing, not a file, in an ignored path (C4 `ignore`, plus `node_modules/`, `.git/`, `dist/`, `build/`, `*.min.*`, `*.lock`), or `formatOnEdit` is false. cd to the git toplevel (or the file's dir). **Formatters only** — `eslint --fix` never runs here (seconds per invocation on type-aware configs; flags legitimately-incomplete intermediate states; lint runs once per turn inside stop-gate's `check-all` lint gate). ## C13 — Parallelism requirements (binding for U6 and U7; added 2026-09-04 at the developer's request)
Wall-clock matters as much as correctness. Anything without a data dependency runs concurrently.
- `build-slices.js`: do NOT pipeline slices strictly in order. Compute **waves**: a slice may start when every slice in its `Depends-on` list has finished and none of its `- **Files**:` paths overlap with a slice still running (the workflow receives `deps: { [id]: number[] }` and `files: { [id]: string[] }` in args when the caller has them; **when either is absent, stage 0 of build-slices runs one `model:'haiku'` agent that reads the plan file and returns `{ deps, files }` per the C7 grammar (schema-enforced) — the workflow never assumes independence silently, and `log()`s the computed waves before starting**).
