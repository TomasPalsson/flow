1. **`CLAUDE_CODE_SUBAGENT_MODEL` / `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`** (skill-and-agent-design.md Finding 11, v2.1.257+) — the actual deterministic, one-env-var replacement for exactly the thing §6 tells Tomas to delete ("Cut the entire Subagent Model Selection table" from CLAUDE.md). SYNTHESIS identifies the problem (a hand-maintained table duplicating flow's routing) but never mentions the primitive that could replace it. Should be in §5 or §6.
2. **`skill-doctor`** (observability-measurement.md Finding 8) — a community plugin that diagnoses skills/agents/CLAUDE.md via Claude Code's own `claude-code-guide` agent, flags skill overlap, and stages/rolls back fixes. This is directly on-point for the exact task §6/§7 assigns Tomas by hand ("run the 7-way frontend cluster through an overlap pass," "merge duplicates," 66→20 skills) and is never mentioned.
3. **Hard cost ceiling / pre-call admission control** — long-running-autonomous.md's TL;DR lists this as one of five "mandatory guardrails" converging across every source, and SYNTHESIS's own gap table (row 13) flags "no cost ceiling" as a gap for `--unattended`/`/goal` use — but §5's deterministic-gates section and the rollout (§7) never implement one. Every other item in that mandatory-guardrail list gets a hook; this one gets none.
4. **`/loop` and cloud Routines** are described in §2 ("Autonomy primitives shipped") but never appear in §4's decision table, even in the "Anything you'd walk away from" row, despite being exactly the shipped primitives for that use case.
5. **Rework rate / AI revert percentage** (observability-measurement.md Findings 11–12) — proposed as the durability-focused counterpart to ccusage/acceptance-rate; §7's "establish baseline" step (weeks 4) cites only ccusage + `code_edit_tool.decision`, omitting the corpus's own suggestion for measuring whether shipped code stays shipped.
6. **OpenAI's structured `docs/` tree + recurring "doc-gardening" agent** (harness-canon.md Finding 3, cited in §2) is presented as OpenAI's core harness move but never translated into a concrete recommendation — PROGRESS.md/REVIEW.md substitute only partially, and Tomas's own audited problem (dead `RTK.md`, stale `better-plan` references) is exactly the failure mode a doc-gardening pass would catch.
7. **`FileChanged` hook as the documented fallback for Bash-driven writes** — claude-code-hooks.md Finding 19 explicitly warns that the `PostToolUse`+`Edit|Write` formatting recipe "only reformats files Claude edited directly... if Claude formats via a Bash command instead, use a `FileChanged` hook for full coverage." SYNTHESIS's `format-lint.sh`/`size-guard.sh` design (matcher `Edit|Write|NotebookEdit`, no Bash coverage) reproduces exactly the gap the source material called out and doesn't mention or close it.

## 2. Recommendations/facts not supported by any cited finding or audit fact

1. **Gap table row 13: "auto-mode `soft_deny` is configured (two entries)"** — this string appears nowhere else in the entire research corpus. `grep -rn soft_deny` across all `.md`/`.txt`/`.tsv` files returns only this one line in SYNTHESIS.md itself. `audit-harness.md` (the file that should back an "audit-only" fact like this) never mentions `soft_deny` or any auto-mode configuration. This looks fabricated or lost in editing — it should either cite where in the config this was found or be removed.
2. **This directly produces an internal contradiction with row 1** (see §4 below): if a real, configured `soft_deny` auto-mode mechanism existed, it would itself be some form of (a)-class enforcement, undercutting row 1's "Zero (a)-class enforcement in the entire harness."
3. **`size-guard.sh` Day-4 rollout thresholds "(600/100)"** (§7 step 5) — presented as a specific starting point with no citation, unlike the `400/60` defaults in the script itself, which §8 candidly discloses as "a defensible mid-band, not a validated number." The looser 600/100 bootstrap numbers get no such disclosure and don't trace to any source in the corpus (the researched range is files 250–300 / functions 20–50).
4. **The `session-context.sh` recipe of injecting a "note: REVIEW.md present" line** (§5) has no corpus citation; it's a reasonable extrapolation of the REVIEW.md concept (review-and-pr-gates.md) but is presented as part of a "deterministic gate" recipe without evidence it's a used pattern anywhere, unlike the rest of that script which mirrors documented examples closely.

## 3. Hook/config snippets vs. claude-code-hooks.md

No outright API errors found — event names, JSON field names (`hookSpecificOutput.permissionDecision`, top-level `decision:"block"` for Stop, `stop_hook_active`, `.tool_input.command`/`.tool_input.file_path`), and exit-code semantics (PreToolUse deny via JSON not bare exit 2; PostToolUse exit 2 = stderr-only feedback since the write already happened; Stop exit/JSON blocks the turn; `SessionStart` bare stdout as context; `matcher:"compact"` for post-compaction re-injection) all match the hooks doc verbatim. Two soft issues:

1. **Coverage gap, not an API error** (repeated from §1.7 above): the `PostToolUse` matcher never includes `Bash`, so any file the model touches via a shell command (`sed -i`, heredoc, etc.) skips `format-lint.sh` and `size-guard.sh` entirely — exactly the scenario the hooks doc's own auto-format recipe warns about and recommends `FileChanged` for.
2. **`stop-gate.sh`'s "nothing changed this turn" check** (`[ -z "$(git status --porcelain)" ] && exit 0`) tests whole-repo dirty state, not this-turn's changes specifically — a logic imprecision (not a hooks-API mismatch) that could let a stale dirty file from an earlier, unrelated turn suppress the gate, or conversely never trigger the "nothing to verify" exit if the repo already had unrelated uncommitted files before the turn started.

## 4. Internal contradictions

1. **Row 1 vs. row 13 of the gap table** (§3): row 1 asserts "Zero (a)-class enforcement in the entire harness"; row 13 asserts an auto-mode `soft_deny` mechanism "is configured." These can't both be quite right, and since row 13's premise is itself unsourced (§2.1 above), the fix is likely to drop the `soft_deny` claim rather than qualify row 1.
2. **SessionStart hook rationale vs. hooks doc's own guidance**: claude-code-hooks.md (Finding 17) notes the `compact`-matcher recipe exists specifically for *re-injecting context lost after compaction*, "distinct from ordinary session-start injection, which Anthropic recommends doing via CLAUDE.md instead." SYNTHESIS's §5 fires `session-context.sh` on bare `SessionStart` too, without addressing this nuance — defensible here since branch/dirty-count/log are inherently dynamic and CLAUDE.md can't produce them, but the synthesis states hook rationale for *why each event fires* without ever mentioning this documented caveat, which a careful reader would expect it to address or rebut.
