# Graphify and the Code-Knowledge-Graph Field for AI Coding Agents (Sept 2026)

## TL;DR

`graphify.net` is **not** the product's home — it is a third-party (or same-author) SEO/directory site ("AI coding tools" comparison hub, monetized via Google AdSense) that promotes and describes an open-source project called **Graphify**, whose real home is `github.com/Graphify-Labs/graphify` and PyPI `graphifyy`. Graphify itself is: an **open-source, MIT-then-Apache-2.0-licensed skill/CLI/MCP server** (not a hosted product) that turns a repo — code, docs, PDFs, images, video — into a **local knowledge graph** (NetworkX + Leiden clustering, Tree-sitter AST for code, LLM calls only for non-code assets) and exposes it to Claude Code, Codex, Cursor, Gemini CLI and 15+ other agents via a `/graphify` skill, a CLI, and an MCP server (stdio or HTTP). Its central pitch is that agents should **query a pre-built graph instead of grepping/reading files**, saving tokens; the vendor's own worked example claims a **71.5× token reduction** (1.7k vs 123k tokens per query on a mixed corpus) — a claim that should be read as vendor-reported, not independently verified.

The `graphify.net` marketing page itself contains factual errors when checked against the primary sources it links to: it claims **MIT license** (GitHub says **Apache-2.0**), claims **"3.7k+ GitHub Stars"** (GitHub API shows **114,624** stars as of Sept 4, 2026), and its "Install & Run" section names an entirely different package (`private-context-mcp` / CLI `private-context`) that doesn't match the real package (`graphifyy` / CLI `graphify`) — strong evidence the site's content is templated/auto-generated and should not be trusted for exact install commands. Use the GitHub README directly.

Graphify sits in a crowded, fast-moving 2026 field of "codebase knowledge graph for AI agents" tools (GitNexus, CodeGraphContext, DeusData/codebase-memory-mcp, vitali87/code-graph-rag, Potpie, Sourcegraph's MCP/Deep Search, Aider's RepoMap, Repomix, cocoindex, Nx/Turborepo project graphs, Greptile). Nearly all of these projects — including Graphify itself — show star counts that grew from zero to tens of thousands within months of creation in 2026, a pattern that (without star-history verification, which I could not obtain) is at minimum worth flagging as unusual and not treated as proof of adoption on its own.

## Findings

### What Graphify actually is

1. **It is an open-source skill + CLI + MCP server, not a SaaS product or a Claude Code "plugin" in the marketplace sense.** Install is `uv tool install graphifyy` (PyPI package name is the double-y `graphifyy`; the CLI binary is `graphify`), then `graphify install` registers a skill file (`.claude/skills/graphify/SKILL.md` for Claude Code, `AGENTS.md` for Codex/OpenCode/others). PRIMARY: [github.com/Graphify-Labs/graphify README](https://raw.githubusercontent.com/Graphify-Labs/graphify/v8/README.md), fetched 2026-09-04.

2. **What it indexes**: code via Tree-sitter AST across ~37-40 grammars (functions, classes, `calls`/`imports`/`inherits`/`mixes_in` edges) done **locally with no LLM call**; plus Markdown/MDX/PDF/Office/images/video/audio/YouTube URLs/live PostgreSQL schemas/package manifests/MCP config files, each of which **does** require an LLM call (uses whatever model your IDE session/API key provides) for semantic extraction. Git history is not directly graphed, but `graphify hook install` adds git hooks so the graph auto-rebuilds on `commit`/`checkout`. PRIMARY: same README, "What files it handles" and "Privacy" sections.

3. **How agents query it**: three CLI/skill verbs — `graphify query "<question>"` (returns a scoped subgraph), `graphify path A B` (shortest path between two named nodes), `graphify explain "<node>"` (node + its edges, tagged `EXTRACTED` vs `INFERRED` vs `AMBIGUOUS` confidence) — plus an MCP server (`python -m graphify.serve graph.json`, stdio or `--transport http`) exposing `query_graph`, `get_node`, `get_neighbors`, `shortest_path`, `list_prs`, `get_pr_impact`, `triage_prs`. Claude Code and Gemini CLI get a `PreToolUse` hook that nudges (or, in `--strict` mode, blocks-once) raw file reads toward the graph query path instead. PRIMARY: same README.

4. **Freshness / staying in sync with changing code**: `graphify hook install` rebuilds the graph automatically on `git commit` and `git checkout`/`git switch` (AST-only, no API cost, runs in background); after `git pull`/merge the user must run `graphify update .` manually (the README recommends aliasing `git pull` to also run this). A custom git merge driver avoids `graph.json` conflict markers between teammates. PRIMARY: README, "Team setup" / "Recommended workflow" sections.

5. **Open-source or paid**: the CLI/skill is open-source (license badge in the repo is **Apache-2.0** per the GitHub API, not MIT as `graphify.net` claims) and free. A **separate, commercial hosted product** — "graphify.com" / "app.graphify.com" — is described in the README as an "early access," "always-on" version, and the README carries a **Y Combinator S26** batch badge, implying the maintainer(s) are a funded startup building a paid layer on top of the free CLI. PRIMARY: README badges/banner ("Early access to the graphify platform is open before the public v1 launch").

6. **Token-savings and accuracy claims (VENDOR CLAIMS, not independently verified)**:
   - "**71.5× Token Reduction**" — homepage stat, elaborated in the worked example: a "Karpathy mixed corpus" (3 GPT framework repos + 5 attention papers + 4 diagrams, ~92k words) produced a 285-node/340-edge graph with "average query cost ~1.7k tokens vs ~123k naive." VENDOR CLAIM. Source: [graphify.net homepage](https://graphify.net/) (fetched via curl 2026-09-04; the URL 403s to automated fetchers/WebFetch, confirming the prompt's premise).
   - FAQ: "On a ~500k-word corpus, BFS subgraph queries stay around ~2k tokens versus ~670k naive." VENDOR CLAIM, same page.
   - README "Benchmarks" table (separate, more elaborate claim set): on **LOCOMO (n=300)**, Graphify reports recall@10 of **0.497** vs mem0's 0.048 and supermemory's 0.149; QA accuracy 45.3% (vs supermemory 49.7%, mem0 27.3%); on **LongMemEval-S (n=50)**, 76% QA accuracy, "tied with dense RAG"; graph build costs "0" LLM credits vs "per-token for most systems." The README states these were scored by an LLM-judge cross-checked against a second judge (90.6% agreement, Cohen's kappa 0.81) and points to a `BENCHMARKS.md` for reproduction — but this is still the vendor's own benchmark harness and methodology, not third-party verification. VENDOR CLAIM. PRIMARY: [Graphify README, "Benchmarks" section](https://raw.githubusercontent.com/Graphify-Labs/graphify/v8/README.md).
   - Security posture claims ("no telemetry," code never leaves the machine for AST parsing, only semantic descriptions sent to the configured model for docs/images) are also vendor-stated but are at least architecturally plausible given the local-Tree-sitter design. PRIMARY: README "Privacy" section.

7. **`graphify.net` vs the real project — discrepancies worth flagging**: (a) License: site says **MIT**; GitHub API says **Apache-2.0**. (b) Stars: site says **"3.7k+"**; GitHub API (2026-09-04) says **114,624** stars, 11,136 forks, 1,255 open issues, repo created 2026-04-03 — i.e., ~114k stars accrued in about 5 months. (c) Install instructions on the marketing page reference a package/CLI (`private-context-mcp` / `private-context`) that has nothing to do with the actual `graphifyy` / `graphify` package — this section appears to be leftover/misapplied template content from a different project page on the same site. These three factual errors, found by cross-checking the marketing page against its own linked GitHub/PyPI sources, are reason to treat `graphify.net` as an unreliable secondary source for exact facts about Graphify, even though its high-level description of the product ("open-source skill that builds multi-modal knowledge graphs...") matches the real README. PRIMARY: [graphify.net](https://graphify.net/) (fetched 2026-09-04) cross-checked against [GitHub API](https://api.github.com/repos/Graphify-Labs/graphify) and [PyPI JSON API](https://pypi.org/pypi/graphifyy/json), both fetched 2026-09-04.

### The peer field

8. **GitNexus** (`abhigyanpatwari/GitNexus`, 46,993 stars, created 2025-08-02, Apache-family "Other" license) — a **client-side, zero-server** knowledge-graph builder that runs entirely in the browser: drop in a GitHub/GitLab/Azure repo URL or a ZIP and it produces an interactive graph plus a "built-in Graph RAG Agent" for chat-style Q&A over the graph. No CLI/MCP-server-first integration path into Claude Code is described in the repo description; it's positioned as a standalone exploration tool rather than an agent-context pipeline. PRIMARY: [GitHub API](https://api.github.com/repos/abhigyanpatwari/GitNexus), fetched 2026-09-04.

9. **CodeGraphContext ("CGC")** — the closest direct match to the "CodeGraph / code-graph-mcp" peer named in the brief. `CodeGraphContext/CodeGraphContext`, 4,155 stars, MIT license, created 2025-08-16. It's an **MCP server + CLI** that "indexes local code into a graph database" (a real graph DB, not in-process NetworkX) "to provide context to AI assistants and developers," usable standalone or connected via MCP to an AI IDE. PRIMARY: [raw README](https://raw.githubusercontent.com/CodeGraphContext/CodeGraphContext/main/README.md), fetched 2026-09-04.

10. **DeusData/codebase-memory-mcp** — 42,173 stars, MIT, created 2026-02-24 (i.e., ~42k stars in about 6 months). Pure-C native binary, no runtime, "15 MCP tools," Tree-sitter AST across 162 languages plus "Hybrid LSP" semantic resolution for 10 of them, indexes an "average repository in milliseconds," the Linux kernel (28M LOC) in ~3 minutes, sub-1ms structural queries. It cites its own **arXiv preprint** (arXiv:2603.27277, *"Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP"*) claiming, across 31 real-world repos, **83% answer quality, 10× fewer tokens, 2.1× fewer tool calls** vs. file-by-file exploration. This is a **vendor-authored preprint claim** (self-published to arXiv, not shown as peer-reviewed) — treat accordingly. PRIMARY: [raw README](https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/README.md), fetched 2026-09-04.

11. **vitali87/code-graph-rag** — 4,964 stars, MIT, created 2025-06-16. Positioned as "the ultimate RAG for your monorepo" combining knowledge graphs with multi-language code editing. PRIMARY: [GitHub API](https://api.github.com/repos/vitali87/code-graph-rag), fetched 2026-09-04.

12. **Sourcegraph** — Cody (the standalone AI coding assistant) appears **discontinued/archived**: `sourcegraph/cody-public-snapshot` and `sourcegraph/sourcegraph-public-snapshot` are both marked `archived: true` on GitHub, last pushed 2025-08-01. Sourcegraph's active 2026 product line for AI agents is **Code Search** (traditional grep/regex-style cross-repo search), **Deep Search** (an agentic search tool that answers natural-language questions and can produce architecture diagrams), and a **Sourcegraph MCP server** that gives agents "programmatic access to your Sourcegraph instance's code search, navigation, and analysis capabilities" **without checking code out locally**. Integration path with Claude Code: point the agent at the Sourcegraph MCP server (remote, not a local index the agent builds itself) — the pitch is explicitly "when your codebase doesn't fit on your laptop or in your context window." PRIMARY: [Sourcegraph blog: "Code Search, Deep Search, or MCP: When to Use Each"](https://sourcegraph.com/blog/the-right-tool-at-the-right-time-using-sourcegraph-search-effectively), April 22, 2026; [GitHub API on cody-public-snapshot](https://api.github.com/repos/sourcegraph/cody-public-snapshot), fetched 2026-09-04.
    - **Evidence quality is unusually good here**: Sourcegraph published a head-to-head benchmark, [*"Sourcegraph MCP server and a cheaper model beat a Mythos-class model alone"*](https://sourcegraph.com/blog/sourcegraph-mcp-and-a-cheaper-model-beat-a-mythos-class-model-alone) (June 16, 2026), on 9 tasks from their own **CodeScaleBench**: Claude Sonnet 4.6 + Sourcegraph MCP (no local checkout) scored **0.698** mean reward at **$1.02** per quality point, vs. "Claude Fable 5" reading a full local checkout with no retrieval scoring **0.568** at **$1.83** per quality point — the cheaper model + MCP won 6 of 9 tasks, with the largest gaps on cross-repository symbol discovery and vulnerability tracing. This is still a **vendor-run benchmark** (Sourcegraph designed CodeScaleBench and ran it), and the post itself caveats that only 9 of the full benchmark's tasks are shown because Fable 5 API access was restricted shortly after release — "treat the result as an early signal, not a settled benchmark" (Sourcegraph's own words). VENDOR CLAIM, but with unusually transparent methodology and a public results explorer.

13. **Aider's RepoMap** — not a knowledge graph in the graph-database sense; it's a **ranked file/symbol map**. Aider parses every file with Tree-sitter, extracts tags (defs/refs), builds a **graph where files are nodes and shared-symbol references are edges**, and runs a **PageRank-style graph ranking algorithm** over it to select the most-referenced identifiers. The map is capped by a token budget (`--map-tokens`, default **1024 tokens**) and is rebuilt/re-ranked on the fly as the chat state changes (which files are already in context shifts what's "most relevant"). It requires no server, no MCP, no persistent index file — it's computed in-process on each aider invocation. Integration with Claude Code specifically: none — RepoMap is internal to the `aider` CLI itself, not exposed as an MCP server other agents could call. PRIMARY: [aider.chat/docs/repomap.html](https://aider.chat/docs/repomap.html) and [repomap.py source](https://raw.githubusercontent.com/Aider-AI/aider/main/aider/repomap.py), fetched 2026-09-04; [Aider-AI/aider GitHub](https://api.github.com/repos/Aider-AI/aider) — 48,732 stars, actively pushed 2026-05-22.

14. **Repomix** (`yamadashy/repomix`, 28,185 stars, actively pushed 2026-09-03) — not a graph at all: it **packs an entire repository into one AI-friendly file** (XML/Markdown/plain text) respecting `.gitignore`, with an optional `--compress` flag that uses Tree-sitter to strip to "key code elements" and shrink token count while preserving structure. No call/import graph, no persistent queryable index, no MCP server — it's a one-shot context-dump tool, most useful for pasting a whole (small-to-medium) repo into a chat UI rather than for an agent doing targeted, iterative queries. PRIMARY: [raw README](https://raw.githubusercontent.com/yamadashy/repomix/main/README.md), fetched 2026-09-04.

15. **Potpie** (`potpie-ai/potpie`, 5,710 stars, Apache-2.0, actively pushed 2026-09-03) — markets itself as a "living **context graph**" that indexes not just code but also SDLC signal: PRs, issues, decisions, team knowledge, source history, via GitHub/Linear/Jira/Confluence integrations, plus a local daemon and CLI (`potpie setup`, `potpie resolve "<task>"`, `potpie search "<query>"`, `potpie record --type decision ...`). Claude Code is a first-class "coding harness" target (`potpie setup --repo . --agent claude`), installing instructions/skills directly. `potpie resolve` is explicitly framed as "pull the context an agent should read before doing a task" — i.e., a pre-flight, scoped-context step rather than free-form graph traversal. PRIMARY: [raw README](https://raw.githubusercontent.com/potpie-ai/potpie/main/README.md), fetched 2026-09-04.

16. **cocoindex** (`cocoindex-io/cocoindex`, 11,462 stars, Apache-2.0, pushed 2026-08-31) — an **incremental data-pipeline framework**, not primarily a graph tool: it re-embeds only the delta when files change ("only the Δ is reprocessed on every change") and ships an "Index your codebase" example that builds a **Tree-sitter-chunked vector index** (pgvector) in ~100 lines of Python — i.e., its default code-indexing recipe is semantic/vector search, not graph traversal, though the framework also documents knowledge-graph-shaped recipes as one of several possible pipeline targets. Its differentiator vs. the graph tools above is explicitly **freshness via incrementality**: it re-syncs only changed inputs rather than requiring a manual rebuild step. PRIMARY: [raw README](https://raw.githubusercontent.com/cocoindex-io/cocoindex/main/README.md) and [code_embedding example README](https://raw.githubusercontent.com/cocoindex-io/cocoindex/main/examples/code_embedding/README.md), fetched 2026-09-04.

17. **Nx project graph / Nx MCP** — Nx (`nrwl/nx`, 29,303 stars) computes a **project graph** (packages/targets as nodes, dependency edges) from workspace config for build orchestration, caching, and "affected" commands. As of the current docs, Nx's **AI-agent story has moved away from exposing the project graph through MCP tool calls**: the docs explicitly reference a blog post titled *"why we deleted most of our MCP tools,"* and now recommend **agent skills** (loaded on demand, not always-resident MCP tools) for "workspace exploration, code generation, task execution," while the Nx MCP server itself is scoped down to CI/Nx Cloud connectivity (self-healing CI, task monitoring, docs) rather than general codebase graph queries. This is a notable, citable data point for the "context cost per query" comparison: a major vendor concluded that keeping a large tool surface (including graph-query tools) permanently loaded in an agent's context was worse than loading domain knowledge on demand. PRIMARY: [nx.dev/docs/reference/nx-mcp](https://nx.dev/docs/reference/nx-mcp), fetched 2026-09-04.

18. **Turborepo** — builds a task/dependency graph from `package.json`/workspace config purely for **build orchestration and caching** (what to rebuild, in what order, what can be cached), not for exposing codebase semantics to a coding agent; it is not a peer in the "help an agent understand code" sense the other tools above target. (General knowledge, consistent with Turborepo's documented purpose; not separately fetched for this report given the tight fit with well-established public docs.)

19. **Greptile** — closed-source SaaS ("22,000+ teams," per homepage), explicitly an **AI code-review** product, not a general-purpose agent-context tool: it "constructs a graph index of your codebase" (files, functions, dependencies) and then runs "a swarm of agents" over that graph to review PRs, catching cross-file/logical bugs and learning team conventions from past review comments. Because it's closed-source and reviews PRs rather than answering ad hoc agent queries, it isn't directly comparable on "context cost per query" the way the open MCP/CLI tools are. PRIMARY: [greptile.com homepage](https://www.greptile.com), fetched 2026-09-04.

## Downsides and failure modes

- **The `graphify.net` marketing page is demonstrably unreliable for exact facts** (wrong license, stars off by ~31×, garbled install instructions pointing at a different package name entirely). Anyone using that page as their only source would run the wrong install command. Always cross-check against `github.com/Graphify-Labs/graphify` directly.
- **Every "code knowledge graph" repo surveyed here (Graphify, GitNexus, DeusData/codebase-memory-mcp) shows tens of thousands of GitHub stars accrued within 3-6 months of repo creation** — Graphify: 0→114,624 stars in ~5 months (created 2026-04-03); GitNexus: 0→46,993 in ~13 months (created 2025-08-02); codebase-memory-mcp: 0→42,173 in ~6 months (created 2026-02-24). I was not able to pull star-history time series to confirm whether this reflects organic virality (plausible — "AI coding agent context" is a genuinely hot 2026 topic) or purchased/bot stars (a known problem for trend-chasing GitHub projects). Treat star counts across this whole category as **weak, unverified popularity signals**, not evidence of quality or reliability.
- **LLM-dependent extraction is a real cost and privacy surface** for every tool that goes beyond pure code (Graphify, Potpie, DeusData's optional LSP layer, cocoindex): docs/PDFs/images/video get sent to whatever model the user has configured, which is a per-token cost and a data-egress point even if raw source code itself stays local.
- **Staleness/sync is manual in most of these tools.** Graphify auto-rebuilds on commit/checkout but requires a manual `graphify update .` after `git pull`; most competitors described here (CodeGraphContext, DeusData, Potpie) don't document fully automatic re-sync on every file change either — cocoindex is the one tool in this set explicitly designed around continuous incremental re-sync as its core value proposition, which is also why it is a narrower single-purpose framework rather than a full graph+skill+MCP package.
- **Benchmark claims across this entire field are vendor-produced.** Graphify's 71.5× and LOCOMO/LongMemEval numbers, DeusData's arXiv preprint (self-published, not shown as peer-reviewed), and even Sourcegraph's CodeScaleBench post are all first-party. Sourcegraph's is the most methodologically transparent of the set (named benchmark, public results explorer, explicit caveat about sample size), but it is still Sourcegraph grading Sourcegraph's own tool. No independent, third-party comparison across these tools was found in this research pass.
- **Nx's own trajectory is a documented counter-example to "more MCP tools = better agent performance."** Nx's docs cite an internal decision to delete most of their MCP tools in favor of on-demand skills — direct evidence from a major vendor that a large, always-loaded graph-query tool surface can be counterproductive for agent context economy, which cuts against the framing (shared by Graphify and several peers) that more graph-query tools are strictly better.
- **Integration paths vary wildly in how "Claude Code-native" they are.** Graphify, Potpie, and Nx ship first-class Claude Code skill/MCP installers; Aider's RepoMap and Repomix are not exposed to Claude Code at all (they're internal to their own CLIs); Sourcegraph and Greptile require pointing at a remote server/SaaS rather than building a local index.

## Concrete setup

**Graphify (Claude Code, from the official README — verify against the live README before running, since PyPI package/version numbers move fast):**

```bash
# 1. Install the CLI (PyPI package name is graphifyy — note the double "y")
uv tool install graphifyy      # or: pipx install graphifyy

# 2. Register the skill with Claude Code (writes .claude/skills/graphify/SKILL.md
#    for a user-global install; add --project to scope it to the current repo)
graphify install
graphify install --project        # repo-scoped instead of user-global

# 3. Make Claude Code always prefer the graph over raw file reads
graphify claude install           # writes CLAUDE.md guidance + a PreToolUse hook
# Optional: block (not just nudge) the first raw source read of a session
graphify install --project --strict

# 4. In Claude Code:
/graphify .                       # build the graph — outputs graphify-out/{graph.html, graph.json, GRAPH_REPORT.md}
/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"

# 5. Keep the graph current
graphify hook install             # auto-rebuild on commit / branch checkout
git config --global alias.gpull '!git pull && graphify update .'   # sync after pulls

# 6. Expose the graph over MCP (e.g. for a shared team server)
python -m graphify.serve graphify-out/graph.json --transport http --host 0.0.0.0 --api-key "$SECRET"
# then point Claude Code's MCP config at http://<host>:8080/mcp
```

Ignore files with a `.graphifyignore` (same syntax as `.gitignore`); add `graphify-out/` and `graph.json` to `.claudeignore` so Claude Code's prompt cache isn't invalidated by every graph rebuild.

**CodeGraphContext (MCP + CLI, peer example):**
```bash
pip install codegraphcontext   # PyPI package name confirmed via README badge
```
(Consult the live [CodeGraphContext README](https://github.com/CodeGraphContext/CodeGraphContext) for the current MCP registration command — it was not fully captured in this pass.)

**Sourcegraph MCP (remote, no local index build):** point your agent's MCP client config at your Sourcegraph instance's MCP endpoint; no local `graphify`-style build/index step is needed because retrieval happens server-side against the instance's existing Code Search index. Exact `.mcp.json` snippet not published in the pages fetched for this report — check Sourcegraph's MCP docs directly before wiring it up.

**Aider RepoMap (no setup — built into `aider`):**
```bash
aider --map-tokens 2048   # raise the repo-map token budget from the 1024 default
```
