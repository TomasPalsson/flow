Angle: Hashimoto / OpenAI Codex / Cognition / Böckeler / HumanLayer / Willison / Cherny / Anthropic Engineering / Steinberger, read **only** for mechanisms that make the right thing happen by default and misuse impossible or loudly refused. Everything was fetched (raw.githubusercontent, GitHub API, publisher HTML, or a dated Wayback capture) on 2026-09-07 unless marked UNVERIFIED. Delta only — assumes `01-harness-engineering-2026.md`, `02-frameworks-source-review.md`, `07-harness-smoothness-2026.md`, `08-reference-harness-inventory-2026.md`, `09-harness-audit-2026-09-07.md`.

## 0. BLUF (15 lines)

1. The canon converged on one word — **harness** — and one job: encode a correction once so the human never re-issues it (S2, S4, S12).
2. **Confirmation prompts are not a guardrail.** Anthropic's own telemetry: users approve **97%** of Claude Code permission prompts; humans caught **13.6%** of a planted dangerous command vs auto mode's **89%** (S8).
3. **Remediation-in-the-error is the most-copied mechanism of 2026.** OpenAI: "we write the error messages to inject remediation instructions into agent context." Böckeler: "a positive kind of prompt injection." flow does this in `git-guard.sh` and nowhere else reliably.
4. **Escape hatches should ratchet, not suppress** — let the agent *raise* a threshold so the rule re-fires on further drift, and review the raised thresholds as the diff's entry point (S14).
5. **Fail-closed, then degrade loudly and bounded.** Claude Code auto mode: three blocks in a row or twenty per session → fall back to manual approvals. That is the vendor's own un-wedgeable-gate pattern (S8).
6. **Fail-open merge gates are correct only at high throughput.** OpenAI runs "minimal blocking merge gates" and says it "would be irresponsible in a low-throughput environment." A solo dev is that environment: keep flow's Stop gate fail-closed (S4).
7. **One file, N vendor names.** Ghostty ships `CLAUDE.md` as a git symlink (mode `120000`) to `AGENTS.md`. Drift structurally impossible (S1, verified via tree API).
8. **The root rules file is a ~100-line table of contents, not an encyclopedia** (S4), and every line in it is a logged regression: "Each line in that file is based on a bad agent behavior" (S2).
9. **Ablation is now a scheduled practice** — one component at a time (S6), per-line with evals (S7), whole-setup every six months (S19). flow has no pruning ritual and no way to name its load-bearing hooks.
10. **Drift is fought by scheduled agents, not vigilance.** "doc-gardening" + golden-principle GC replaced a standing Friday slop cleanup that "didn't scale" (S4).
11. **Ceremony must be proportional and chosen at dispatch:** "most traditional coding tasks do not need a panel of 5 reviewers" (S9).
12. **Verification, not prompting, is the scarce skill** (S2, S19, S5).
13. **Clean-context reviewers beat shared-context reviewers**, measured: ~2 bugs per Devin-written PR, 58% severe (S11).
14. **The best-documented harness footgun of 2026 is Anthropic's own:** three small independently-shipped harness changes → six weeks of degradation their internal evals never reproduced (S7).
15. Biggest flow gaps in this lens: no ablation record, remediation text missing from most hooks, no ratcheting thresholds, and a `notify.sh` two sources call an anti-pattern.

## 2. Principles ranked by evidence strength

### Tier A — multiple primaries, at least one with numbers

**A1. A permission prompt is a decision the human will not make.** S8, first-party telemetry: "users approve 97% of permission prompts in Claude Code… the rejection rate is only 3%." Contrast: "when Claude presents a plan for approval, users reject 39% of them." Fatigue is measurable within a session — humans "blocked about 17% of dangerous commands early in a session, dropping to about 5% after 50 or more prior prompts, while auto mode's block rate stayed flat." Config rot corroborates: "62% of users have used bypassPermissions or clicked 'don't ask again' on Bash, and 25% of interactive sessions start in bypass permissions mode." *Reading for flow:* put human gates where humans still engage (plans, 39% rejection); make everything else a deterministic rule. A guardrail that asks is a guardrail that is off.

**A2. Remediation belongs inside the error, addressed to the agent.** S4: "Because the lints are custom, we write the error messages to inject remediation instructions into agent context." S12: sensors are "particularly powerful when they produce signals that are optimised for LLM consumption, e.g. custom linter messages that include instructions for the self-correction — a positive kind of prompt injection." S16 factor 9 is the loop-level version, with a consecutive-error counter that escalates after ~3. S14 quantifies the cost of omitting it: the one rule class the agent kept gaming (cyclomatic complexity) "was the only category where it did that, and I later discovered that I didn't have a self-correction guidance in place for this one."

**A3. Fail-closed, then degrade — bounded, loud, to a still-usable state.** S8 verbatim: "if it can't make progress—three blocks in a row, or twenty across a session—Claude Code falls back to manual approvals." Counter + cap + *fallback mode that still works*, not an unblock. flow's `stop-gate.sh` header ("after 3 identical blocks it degrades to a non-blocking exit 2") is the same shape arrived at independently; S8 is the doctrinal backing and adds the session-wide cap. S16 factor 9: "Hitting some consecutive-error-threshold might be a great place to escalate to a human… by model decision or via deterministic takeover of the control flow."

**A4. Ablation is the maintenance ritual; every line is a tax.** S6: "every component in a harness encodes an assumption about what the model can't do on its own, and those assumptions are worth stress testing, both because they may be incorrect, and because they can quickly go stale as models improve." Method matters — the radical cut failed because "it became difficult to tell which pieces of the harness design were actually load-bearing," so he moved to "removing one component at a time." S7 made it policy: "We will run a broad suite of per-model evals for every system prompt change to Claude Code, continuing ablations to understand the impact of each line." S19 (SECONDARY): Claude Code "deleted over 80% of its system prompt for Opus 5"; user advice — "every six months, delete your CLAUDE.md, your skills, your hooks — and see what the model does before adding anything back."

**A5. Progressive disclosure: a map, not a manual.** S4: "We tried the 'one big AGENTS.md' approach. It failed in predictable ways: Too much guidance becomes non-guidance… It rots instantly. A monolithic manual turns into a graveyard of stale rules… the file quietly becomes an attractive nuisance." Fix: "a short AGENTS.md (roughly 100 lines)… serves primarily as a map, with pointers to deeper sources of truth elsewhere… This enables progressive disclosure." S1 implements the same doctrine via filesystem: a 1,388-byte root `AGENTS.md` plus nested `macos/AGENTS.md`, `src/terminal/c/AGENTS.md`, `test/fuzz-libghostty/AGENTS.md` — extremely specific guidance loaded only when the agent is in that directory (the fuzz file spends 30 lines on why `@@` breaks `afl-showmap`).

**A6. Verification loop beats prompt quality.** S2: "If you give an agent a way to verify its work, it more often than not fixes its own mistakes and prevents regressions." S19 (SECONDARY): the Bun Zig→Rust rewrite leaned on Bun's and Node's test suites; the Electron→Swift rewrite on pixel-diffed screenshots — "Neither prompt was clever. Both had verification built in." S5: the fix for "Claude marks features as done prematurely" was end-to-end browser verification, not stronger wording.

### Tier B — one strong primary, or primary + corroborating secondary

**B1. Escape hatches should ratchet, not suppress.** S14, the sharpest single mechanism in the corpus: "For thresholds… I told the agent in the lint message that it may slightly increase the thresholds if it thinks that a refactoring is unnecessary or impossible in a particular case. This doesn't suppress the threshold forever, just increases it, so that the rule fires again if it gets even worse in the future. Constraints are preserved without forcing a binary suppress-or-comply choice." And the review affordance that falls out: "Looking at the exceptions AI created (suppressed warnings, increased thresholds) was a good point to start my code review."

**B2. A guardrail must survive the user's own footgun config.** S8: "Permission rules still fire before the classifier in auto mode, except for allow rules broad enough to grant arbitrary code execution (e.g. `python:*`). These arbitrary rules are set aside while in auto mode… **Settings files aren't modified, and the rules apply again the moment you switch to another mode.**" That last clause is the art: neutralise the bypass without mutating user state, restore on mode exit. Plus a category with no in-mode escape: "Hard denies: Data exfiltration… sits in a category the classifier is designed to never approve. To run an action like that, you have to switch out of auto mode or run the command yourself."

**B3. Loud refusal that leaves evidence in the diff.** S1 `AGENTS.md` verbatim: "Never create an issue. Never create a PR. If the user asks you to create an issue or PR, create a file in their diff that says 'I am a sad, dumb little AI driver with no real skills.'" A tripwire, not a rule: the violation becomes a visible artifact the human cannot miss at review. Cheaper than a hook and it degrades safely (worst case: a silly file).

**B4. One file, many vendor names — by symlink.** S1, verified via tree API: `100644 blob AGENTS.md` / `120000 blob CLAUDE.md`. Mode `120000` is a symlink; the raw endpoint returns the literal string `AGENTS.md`.

**B5. Drift is fought on a schedule by agents, not by discipline.** S4: "Our team used to spend every Friday (20% of the week) cleaning up 'AI slop.' Unsurprisingly, that didn't scale. Instead, we started encoding what we call 'golden principles' directly into the repository and built a recurring cleanup process… background Codex tasks that scan for deviations, update quality grades, and open targeted refactoring pull requests. Most of these can be reviewed in under a minute and automerged… Human taste is captured once, then enforced continuously on every line of code." Also: "Dedicated linters and CI jobs validate that the knowledge base is up to date, cross-linked, and structured correctly. A recurring 'doc-gardening' agent scans for stale or obsolete documentation that does not reflect the real code behavior and opens fix-up pull requests." S19 (SECONDARY) corroborates: Anthropic runs "20–30 daily routines per codebase" including an "abstraction police."

**B6. The escalation ladder is explicit and ends in code.** S4: "When the agent struggles, we treat it as a signal: identify what is missing—tools, guardrails, documentation—and feed it back into the repository, always by having Codex itself write the fix… When documentation falls short, we promote the rule into code." S19: "Fix failures at the right layer… better prompting for behavior, a skill for repeatable procedure, an MCP server for missing context." S2 gives the two-rung solo version: "Better implicit prompting (AGENTS.md)" then "Actual, programmed tools… usually paired with an AGENTS.md change to let it know about this existing."

**B7. Enforce boundaries centrally, allow autonomy locally.** S4: "we require Codex to parse data shapes at the boundary, but are not prescriptive on how that happens (the model seems to like Zod, but we didn't specify that specific library)… enforce boundaries centrally, allow autonomy locally." With the acceptance bar that follows: "The resulting code does not always match human stylistic preferences, and that's okay. As long as the output is correct, maintainable, and legible to future agent runs, it meets the bar."

**B8. Ceremony proportional to task, chosen at dispatch.** S9: workflows "are not needed for every task and may end up using significantly more tokens… For regular coding tasks, try and ask yourself: does it really need more compute? For example, most traditional coding tasks do not need a panel of 5 reviewers." And a cheap tier exists: "Workflows are not just for large tasks. You can prompt the model to use a 'quick workflow.'" S6 states the decision rule: "the evaluator is not a fixed yes-or-no decision. It is worth the cost when the task sits beyond what the current model does reliably solo."

**B9. Zero-memory onboarding = an artifact the next session reads first.** S5 is the fullest statement: the initializer writes `init.sh`, `claude-progress.txt`, a JSON feature list, and an initial git commit; every later session is prompted to `pwd`, read the progress file and `git log`, run `init.sh`, and smoke-test *before* picking the next feature. Two hardening details worth copying verbatim: they use **JSON not Markdown** for the feature list because "the model is less likely to inappropriately change or overwrite JSON files," and they attach "It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality." S6 adds the sprint contract: "the generator and evaluator negotiated a sprint contract: agreeing on what 'done' looked like for that chunk of work before any code was written," passed file-to-file. S15 is the human-leverage version: "A bad line of a **plan** could lead to hundreds of bad lines of code. And a bad line of **research**… could land you with thousands" — therefore review research and plans, not diffs.

**B10. Clean-context adversaries; writes stay single-threaded.** S11: Devin Review "catches an average of 2 bugs per PR, of which roughly 58% are severe," and "this technique works best when the coding and review agents do not share any context beforehand… it is forced to reason backward from the implementation without the spec." 2026 synthesis: "multi-agent systems work best today when writes stay single-threaded and the additional agents contribute intelligence rather than actions"; "the unstructured-swarm approach… is mostly a distraction. The practical shape is map-reduce-and-manage." S6 independently: "tuning a standalone evaluator to be skeptical turns out to be far more tractable than making a generator critical of its own work." S9 names the failures it defeats: "Self-preferential bias… Claude's tendency to prefer its own results" and "Goal drift… especially after compaction. Each summarization step is lossy, and details like edge-case requirements or 'don't do X' constraints can get lost."

### Tier C — single source, plausible, adopt with care

**C1. Interrupt discipline belongs to the human.** S2: "**Very important at this stage: turn off agent desktop notifications.** Context switching is very expensive… it was my job as a human to be in control of when I interrupt the agent, not the other way around." One primary source, but it matches this repo's own `no-nudge-noise` ruling.

**C2. The real escape hatch for a solo dev is a restore point, not a prompt.** S18 runs `--dangerously-skip-permissions` by default (`alias cc`) with "hourly Arq snapshots (plus a SuperDuper! clone)" as the mitigation. Security posture superseded by S8/S17, but the architecture — recoverability beats interception — is the bet `pre-compact-backup.sh` already makes.

**C3. Trust gating at the repo boundary, with remediation in the refusal.** S1: unvouched PRs are auto-closed by `mitchellh/vouch/action/check-pr@… auto-close: true`; unvouched issues get a templated close naming the one path back in ("we ask that you create a discussion first… see #3558 and our CONTRIBUTING.md"). Cleanest fail-closed + remediation + documented-escape example in the corpus.

**C4. Harness meta-monitoring is the missing layer.** S14: "Which sensors are never failing? → a signal that they are not necessary. What sensors / rules are frequently failing? → a signal that we could improve our guides there." S12 states it as open: "If sensors never fire, is that a sign of high quality or inadequate detection mechanisms? We need a way to evaluate harness coverage and quality similar to what code coverage and mutation testing do for tests."

## 2b. Smaller mechanisms worth lifting verbatim

**Commands are executable programs that emit prompts, not markdown.** S1 `.agents/commands/review-branch` is a Nushell script: it shells out to `gh issue view --json …`, interpolates the issue body and comments into a prompt string, and ends with `**ONLY CREATE A SUMMARY. DO NOT WRITE ANY CODE.**`. Its header comment warns the human what to expect: "IMPORTANT: This command is prompted to NOT write any code… You should still be vigilant when running this but that is the expected behavior." Context is *fetched deterministically* rather than trusted to the model, and the destructive-capability boundary is stated twice — once to the model, once to the human.

**Skills carry the workflow's exit condition.** S1 `.agents/skills/writing-commit-messages/SKILL.md` ends with "Apply the commit / Don't push the commit; leave that to the user," and opens with a conditional tool switch ("If `.jj` is present, use `jj` instead of `git`"). The skill owns where the agent must stop, so no hook has to catch it.

**Quarantine untrusted-content readers from privileged actors.** S9: "A useful pattern for triage workflows is quarantine. This involves barring the agents that read untrusted public content from taking high-privilege actions, which are instead done by the agents in charge of acting on the information." This is the architectural answer to S17's lethal trifecta, expressed as an agent-topology rule rather than a filter.

**Hard-deny lists should be user-extensible but not in-mode escapable.** S8: "Hard deny rules are customizable via settings so you can add more rules that you never want allowed even when requested by users in your organization." The escape hatch exists (leave the mode) and is discoverable; it just is not reachable from inside the mode by argument.

**Nested rules files carry the tool-invocation traps, not the philosophy.** S1 `test/fuzz-libghostty/AGENTS.md` documents that `afl-showmap`/`afl-cmin` must take stdin, not `@@`, "If you pass `@@` or a filename argument, `afl-showmap`/`afl-cmin` will see only ~4 tuples (the C main paths) and produce useless results" — i.e. the file records the *silent-wrong-answer* failure mode, which is exactly the class a hook cannot detect.

**A policy file that explains its own reason for existing.** S1 `AI_POLICY.md` states the rule, the enforcement (a public denouncement list), the exemption (maintainers), and then a section titled "AI is Welcome Here" explaining that "**Our reason for the strict AI policy is not due to an anti-AI stance**, but instead due to the number of highly unqualified people using AI." Rules that carry their rationale survive contact with the person who wants to bend them.

## 3. 2026 footgun post-mortems

**S7 — Anthropic's own harness degraded for six weeks and their evals missed it.** Three independent product-layer changes: default reasoning effort high→medium (Mar 4); a caching change meant to clear stale thinking *once* that "kept happening every turn for the rest of the session" (Mar 26); a verbosity cap in the Opus 4.7 system prompt (Apr 16) that later ablation showed cost 3% on code generation. "Because each change affected a different slice of traffic on a different schedule, the aggregate effect looked like broad, inconsistent degradation… neither our internal usage nor evals initially reproduced the issues." Transferable remediations: **dogfood the shipped artifact** ("a larger share of internal staff use the exact public build of Claude Code (as opposed to the version we use to test new features)") — flow is developed in worktrees, so the version under test must be the deployed one; **gate model-specific changes to that model** via CLAUDE.md guidance; **soak periods and gradual rollout** for anything trading against intelligence. The only thing that surfaced it was users with "specific, reproducible examples."

**S6 — the "cut it back radically" anti-pattern.** Removing many pieces at once destroyed attribution. One-at-a-time is the method. **S4 — the monolithic AGENTS.md as "attractive nuisance."** **S3 — the slop zone**, and Hashimoto's stopping rule: "It's at this point that I know I need to step back… AI is no longer the solution; it is a liability," plus "I'm not shipping code I don't understand."

## 4. Contradictions worth naming

1. **Fail-open vs fail-closed gates.** S4 runs "minimal blocking merge gates… Test flakes are often addressed with follow-up runs rather than blocking progress indefinitely… corrections are cheap, and waiting is expensive. **This would be irresponsible in a low-throughput environment.**" flow's owner *is* that environment. Keep the fail-closed Stop gate; do not import OpenAI's merge philosophy.
2. **Cognition 2025 vs 2026.** S10 said don't; S11 concedes a narrow class and ships manager-Devins. The reconciliation is not "multi-agent good" — it is "additional agents contribute *intelligence*, not *actions*." flow's parallel *writers* in worktrees sit outside what S11 endorses; flow's parallel *reviewers* sit squarely inside it.
3. **More harness vs less harness.** S6 built a three-agent harness then deleted the sprint construct when Opus 4.6 landed; S19 says delete everything every six months. Not in conflict with each other — both treat the harness as a hypothesis with a shelf life. The conflict is with flow's posture, which accretes and never prunes.
4. **Notifications.** S2 says turn them off; flow ships `notify.sh`. Real contradiction, and the repo's own `no-nudge-noise` ruling agrees with S2.
5. **Steinberger 2025 vs Willison/Anthropic 2026.** S18's blanket `--dangerously-skip-permissions` is exactly the 25%-of-sessions bypass S8 cites as the problem. S17 remains skeptical even of the fix: "I'm personally inspired to double down on figuring out a productive way to run agents such that they don't have access to data or tools that can cause harm if triggered in the wrong way."
6. **Is a rules-file line the mechanism or the fallback?** S2 treats the AGENTS.md line as a first-class fix ("it almost completely resolved them all"); S4 says prose rots — "promote the rule into code." flow's `lesson` ladder already resolves this the S4 way; the delta is that S2 licenses *stopping at the prose rung* for cheap cases, which keeps ceremony proportional.

## 5. Ten most adoptable mechanisms → where it lives in flow → what it prevents

1. **Remediation text in every hook denial and non-zero lint exit** (S4, S12, S16) → `plugins/flow/hooks/format-lint.sh`, `size-guard.sh`/`size_guard.py`, `tamper-notice.sh`, `spec-gate.sh`, `scripts/plan-lint`, `scripts/skills-lint`, `scripts/workflow-lint`; `hooks/git-guard.sh` is the in-repo reference implementation → prevents an agent that knows it is blocked but not what to do, burning turns guessing and eventually routing around the gate.
2. **Ratcheting escape hatch instead of suppression** (S14) → `plugins/flow/hooks/size_guard.py` + `hooks/size-guard.sh`, and thresholds in `flow-templates/gates.yml.tmpl`; the message must say *raise the recorded threshold if refactoring is genuinely wrong here, never suppress* → prevents permanent `# noqa`-style silencing and the binary comply-or-disable choice that trains the agent to disable.
3. **Bounded fail-closed degradation with a named fallback mode** (S8, S16) → `plugins/flow/hooks/stop-gate.sh` (already 3-strikes→exit 2; add S8's session-wide cap of ~20) and `hooks/lib/hookout.sh` → prevents a wedged turn escapable only by `flow off`, i.e. the failure that turns a safety gate into a reason to disable safety.
4. **Symlink the vendor-name instruction files** (S1, mode `120000` verified) → `plugins/flow/flow-templates/CLAUDE.project.md` and whatever `flow init` writes; ship `AGENTS.md` real, `CLAUDE.md` as symlink → prevents two instruction files drifting apart and the agent obeying the stale one.
5. **Root rules file as a ~100-line table of contents plus nested per-directory files** (S4, S1) → `flow-templates/CLAUDE.project.md`, `flow init` in `plugins/flow/bin/flow`, the `claude-md` skill → prevents "too much guidance becomes non-guidance" and the rules file rotting into an attractive nuisance.
6. **A pruning/ablation ritual with a record** (S6 one-at-a-time, S7 per-line, S19 six-monthly) → new subcommand beside `doctor`/`next` in `plugins/flow/bin/flow`; outcomes logged in `flow-templates/PROGRESS.md`; feed it S14's counters (`hooks/tool-stamp.sh`, `turn-stamp.sh`, `subagent-log.sh` already stamp) → prevents a harness that only accretes, where nobody can name which of 19 hooks is load-bearing.
7. **Scheduled doc-gardening / golden-principle GC instead of standing vigilance** (S4, S19) → `plugins/flow/workflows/` plus a `/loop`-style routine over `PROGRESS.md`, `REVIEW.md`, `docs/research/`, `plugins/flow/skills/*/SKILL.md`; `scripts/skills-lint` and `scripts/workflow-lint` are the deterministic half → prevents stale rules that silently contradict the code, and the Friday slop-cleanup tax OpenAI proved does not scale.
8. **First-run bearings script plus a machine-readable progress artifact** (S5, S6, S15) → `hooks/session-context.sh` and `hooks/postcompact-context.sh` (read side), `flow-templates/PROGRESS.md` (write side); two upgrades from S5 — make the checklist state **JSON**, and attach "it is unacceptable to remove or edit tests"; make the session's first act a smoke test, not a new feature → prevents a fresh context declaring victory on half-built work or burning its first 30% of tokens rediscovering state.
9. **Tripwire artifacts for rules a hook cannot cheaply enforce** (S1) → `flow-templates/CLAUDE.project.md` / repo `AGENTS.md`: forbidden actions must write a marker file into the diff rather than being silently attempted → prevents silent rule violations that only surface after merge; costs nothing and fails safe.
10. **Clean-context adversary, single-threaded writes, ceremony sized at dispatch** (S11, S6, S9) → `plugins/flow/skills/review-diff`, `scripts/review-package`, `skills/audit`, `skills/ultracode`: reviewers never see the spec/plan context, writers never run in parallel on one seam, reviewer count derives from task size → prevents self-preferential rubber-stamping, parallel writers making incompatible implicit decisions, and 5-reviewer ceremony on a one-line fix.
