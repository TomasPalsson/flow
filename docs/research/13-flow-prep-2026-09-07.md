# `/flow:prep` — grilling the idea before the spec, without the model going ham (2026-09-07)

Synthesis of a six-angle research sweep (`raw/prep/sweep-report.md`, 60 claims, 26 re-fetched and
verified against primary sources; per-claim JSON in `raw/prep/sweep-claims.json`) plus an in-tree read of
every interview-shaped skill in `plugins/flow/skills/`. **PRIMARY** = fetched 2026-09-07 or read from
this tree; **SECONDARY** = a walkthrough or prior research doc; **UNVERIFIED** = located, not re-fetched.
Builds on `11-flow-redesign-2026.md` (the `/flow:spec` + `/flow:next` design on the sibling worktree)
and `10-idiot-proof-harness-2026.md` §2 P7 (ceremony by computed predicate). Cited, not repeated.

## 1. BLUF

1. **Prep is the documented shape, not an invention.** Anthropic's own best-practices page (PRIMARY,
   verbatim): *"For larger features, have Claude interview you first… Keep interviewing until we've
   covered everything, then write a complete spec to SPEC.md."* Six frameworks (superpowers, gsd,
   spec-kit, BMAD, Kiro, OpenSpec) all put a discovery step before the spec and all hand forward a
   **decisions artifact, never a transcript**.
2. **"Going ham" has three evidenced causes, and "be concise" is not a fix for any of them.**
   (a) No scope fence — removing the explicit scope declaration from the prompt moved Claude Code's
   measured out-of-scope rate from **0.0 % to 17.1 %** (PRIMARY, arXiv 2605.18583). (b) No verification
   criterion — agents build to the visible check, not the request (PRIMARY, arXiv 2606.28430). (c)
   Sycophantic assent — "agreed, agreed, agreed" is Pocock's own top-reported grill-me failure (PRIMARY).
3. **Where ham lives in flow today is the reading load and the recommend-first rule.** A Medium spec
   run makes the model read **1,221 lines** before drafting (SKILL 266 + question-bank 278 + template 401
   + doctrine 200 + forces 76, PRIMARY `flow-spec/`). Every discovery turn is *"Recommendation →
   reasoning → confirm or correct?"* (`flow-spec/SKILL.md:70`), so the model generates a position on all
   8 categories whether or not the user has one. grill-me does the opposite — *"Ask each question open,
   without hinting at the answer you'd pick"* (`grill-me/SKILL.md:8`) — and writes nothing down.
4. **The artifact is the product; three buckets, not two.** gsd's CONTEXT.md carries **Decisions**
   (`D-01`, locked), **Deferred** (must not appear), and **Claude's Discretion** (decide alone). The third
   bucket is what stops the spec writer from either re-asking or silently guessing. (Decisions/Deferred
   PRIMARY; the Discretion block SECONDARY — verify against gsd-core before copying the label.)
5. **The anti-re-interview rule lives in the consumer.** gsd (PRIMARY, verbatim): *"the planner reads
   CONTEXT.md to know which decisions are locked. It will not re-ask questions already answered here."*
   flow-spec's consolidate-mode gate (`flow-spec/SKILL.md:64`) already has the right shape; it only lacks
   a file to consolidate *from*.
6. **Budget 6–12, cap hard, name the split signal.** Saturation research: ~80 % of codes by interview 6,
   saturation by 12 (PRIMARY, Guest et al. 2006). spec-kit caps clarify at **5** (PRIMARY). Pocock's FAQ:
   two hundred questions means *"the scope was too large"* — split it (PRIMARY).
7. **Mechanics are settled by the docs.** `disable-model-invocation: true` so prep never fires mid-task;
   **no** `context: fork` (it *severs* the conversation that motivated the interview — a reversed claim
   in the raw research is corrected in §6); the interface between prep and spec is a file on disk,
   because no skill can call another.
8. **Prep is where the route is decided.** superpowers classifies spike / bounded / architectural
   *before the first question* (PRIMARY) and `11-flow-redesign` §3.6 gives flow the same three rungs.
   Prep's last line should be the route, so a bounded change ends in chat and never reaches `/flow:spec`.

Two facts fall out. First, the plugin has **no** skill that both interviews and writes a decision file;
grill-with-docs writes a glossary, which is deliberately "devoid of implementation details" (`:76`).
Second, the plugin disagrees with itself on when to recommend: grill-me after, flow-spec before. Pocock's
own history settles it — recommend-with-question was a *speed* addition bolted on later (*"the new thing
that I added recently was for each question, provide your recommended answer"*, PRIMARY), and Osmani's
`interview-me` pairs each question with a **guessed answer plus a confidence percentage** (UNVERIFIED).
A stated hypothesis the user can correct is not a leading question; a hidden one is.

## 3. Why the model goes ham — mechanism by mechanism

| Failure | Evidence | What stops it | Where it belongs |
|---|---|---|---|
| Scope creep / out-of-scope edits | 0.0 % → 17.1 % when the scope line is removed (PRIMARY) | An explicit **Not this** list carried into the artifact and quoted by the spec | prep writes it; spec copies it verbatim into §2.2 Non-goals |
| Building to the test | agents optimise toward the visible check (PRIMARY) | One end-to-end **verification criterion** stated by the user, not invented | prep asks it last; spec's launch criteria inherit it |
| Sycophantic assent | Pocock's top failure; Anthropic sycophancy papers (UNVERIFIED) | Explicit confirmation rule: silence and "sounds good" do not lock a decision (Osmani, UNVERIFIED); prep restates and asks for a number, a name or a specific | prep |
| Scope balloons on "ungrillable" questions | *"The agent keeps rephrasing, you keep guessing, and the scope grows to fill the uncertainty"* (PRIMARY, aihero) | Refuse feel/aesthetic questions; route to a prototype or `design:vary` | prep |
| Reviewer-driven gold-plating | *"Chasing every finding leads to over-engineering"* (PRIMARY, Anthropic) | "Flag only gaps that affect correctness or the stated requirements" | spec-judge prompt, review lenses |
| Infinite exploration | Anthropic names it as a pattern (PRIMARY) | Scope the codebase read to the files the answer needs; grill-me's rule is already right | prep |
| Reading-load drift | 1,221 mandatory lines per spec run (PRIMARY) | `11-flow-redesign` §3.3: template 401 → ~110, bank 278 → ~65 | spec |
| Over-generation on every turn | recommend-first on all 8 categories (`flow-spec/SKILL.md:70`) | Hypothesis + confidence, one line; the user's words fill the artifact, not the model's | prep |

The three with numbers behind them — scope fence, verification criterion, explicit confirmation — are the
ones to make **structural**: a `prep lint` that fails on an empty **Not this** section or a missing
**Verify** line is a check the model cannot route around; a sentence asking it to be careful is not
(`10-idiot-proof` P1–P5).

## 4. Prior art, one line each (all PRIMARY unless marked)

- **superpowers `brainstorming`** — *"Only one question per message"*; classify spike / bounded /
  architectural first; *"YAGNI ruthlessly"*; *"The gate is the approval, not the design's length"*;
  hand-off is a prohibition: *"the ONLY skill you invoke after brainstorming is writing-plans"*; too big →
  decompose into sub-projects *upstream*, never in the plan.
- **superpowers `writing-plans`** (the consumer) — copies spec constraints *"verbatim"* into a Global
  Constraints block; re-scoping *"should have been broken into sub-project specs during brainstorming"*.
- **gsd `discuss-phase` → CONTEXT.md** — purpose: *"Extract implementation decisions that downstream
  agents need"*; 7 blocks, **no YAML frontmatter**, `D-NN` IDs; `<deferred>` block. Assumptions mode
  (SECONDARY): read the codebase, emit assumptions with evidence + confidence, user only confirms.
- **spec-kit `/speckit.clarify`** — *"Present EXACTLY ONE question at a time"*, *"Maximum of 5 total
  questions"*; only ask what is answerable by 2–5 options or ≤5 words; `- Q: … → A: …` log **and** the
  answer is routed into the affected spec section; atomic overwrite after each answer so a dropped
  session loses one answer, not the interview; ≤3 `[NEEDS CLARIFICATION]` inline markers.
- **spec-kit `spec-driven.md`** — *"Don't guess: If the prompt doesn't specify something, mark it"*;
  checklist item *"No speculative or 'might need' features"*.
- **Kiro** (UNVERIFIED) — EARS requirements; Quick Spec *front-loads* the clarifying questions.
- **OpenSpec** (UNVERIFIED) — `proposal.md` declares intent and scope first; deltas marked ADDED /
  MODIFIED / REMOVED so growth beyond the declaration is visible in review.
- **Interview science** — one-at-a-time halves missing data at no validity cost (PRIMARY, PLoS ONE 2012),
  but a practitioner warns serial delivery of a prepared list feels punishing and literal five-whys makes
  people defensive (UNVERIFIED, Brandenburg). Wiegers' words-to-avoid list (UNVERIFIED) is the
  quantify-every-adjective rule flow-spec already has (`question-bank.md:100-113`).

## 5. The design

### 5.1 Position in the pipeline

```
/flow:prep <idea>            interview → .specs/NNN-slug/PREP.md → route
        │ bounded  → short design in chat, one LEDGER.md line, no spec (11-flow-redesign §3.6)
        │ spike    → a reported recommendation, no spec
        ▼ oneshot | dispatch
/flow:spec                   reads PREP.md, consolidate mode, never re-asks a D-NN
```

`/flow:spec` alone keeps working exactly as `11-flow-redesign` §3.1 describes (one batched turn of
pre-answered assumptions); prep is the **serial, user-led** door for ideas that are not yet decided. That
maps onto the redesign's `--interview` flag — prep *is* that flag, promoted to a command so it has an
artifact and a stop rule of its own.

### 5.2 `PREP.md` — the contract

No frontmatter (gsd's rule; it is a body-only file). Written **after every answer**, not at the end.

```markdown
# Prep — Entry tagging
Gathered: 2026-09-07 · Questions: 7 of 12 · Route: dispatch · Status: ready for spec

## Decisions            (locked — spec copies verbatim, never re-asks)
- D-01 Tags are per-entry, free text, max 5. — user, Q2
- D-02 Duplicate tag → 409, not silent dedupe. — user, Q4

## Not this             (spec §2.2 Non-goals, verbatim; build must not touch)
- No tag hierarchy. No server-side search. No admin UI.

## Discretion           (spec/build decides alone; do not ask)
- Empty-state copy, chip ordering, breakpoint below 375px.

## Assumptions          (stated by prep, confirmed or corrected by the user)
- A-01 Postgres already hosts entries (evidence: db/schema.sql:12) — confidence high — confirmed Q1
- A-02 ~1k tags per user is the ceiling — confidence low — user: "no idea, assume 10k"

## Verify               (the one end-to-end check the user will accept)
- Tag an entry at 375px, reload, the chip is still there; `pytest tests/test_tags.py` green.

## Open                 (≤3, or the scope is too big — split)
- Q: rename vs delete-and-recreate? → deferred to spec
```

Each of the six sections answers a question the spec writer would otherwise ask or guess. Stable IDs
(`D-NN`, `A-NN`) give spec-judge and the review something to cite (gsd, PRIMARY). The `Questions: n of
12` line is the budget counter, kept in the file so a lint can read it rather than the model remembering it.

### 5.3 Interview rules for prep (the grill-me lineage, corrected)

1. **Classify before the first question** — spike / bounded / architectural, said out loud, user can
   override (superpowers). Bounded ends prep with a design in chat; there is no spec to prep for.
2. **Explore first, ask second.** Anything answerable from the tree is stated as an `A-NN` with a
   `path:line` and a confidence, and the user confirms or corrects (grill-me `:12`, gsd assumptions mode).
3. **One decision per turn**, open phrasing, **then** a one-line hypothesis with a confidence — *"Mr
   Claude's guess: 409 on duplicate, 70 %"* — so a one-word reply locks it (Pocock's addition, Osmani).
   Naming a decision's own candidates is still one question (grill-me `:10`).
4. **Only ask what is answerable** in 2–5 options or ≤5 words (spec-kit). Interaction feel, aesthetics
   and "does this look right" are **ungrillable** — say so and route to a prototype or `design:vary`.
5. **Two mandatory probes** survive from flow-spec: the negative-scope question (`SKILL.md:72`) fills
   **Not this**; the quantification probe (`question-bank.md:100`) fires on every adjective.
6. **Explicit confirmation only.** A decision moves to **Decisions** on a number, a name or a specific.
   "Sure", "agreed", silence → restate once, then record as an `A-NN` low-confidence, not a `D-NN`.
7. **Budget 12, checkpoint at 6.** At six, print the file's Decisions/Open counts and ask "continue or
   write?" (usirin's 5–8 checkpoint, UNVERIFIED; Guest's 80 %-by-6). At twelve, stop; more than three
   **Open** lines is the split signal — offer to decompose into sub-preps, never a bigger spec.
8. **The last question is always Verify.** "What single thing would you check to believe this shipped?"
   The building-to-the-test result says the spec must inherit this, not invent it.
9. **Stop when the next three answers are predictable** (Osmani's rule; flow-spec's convergence test
   `SKILL.md:76` is the same rule stated once).

### 5.4 What changes in `/flow:spec`

- **Consolidate-mode gate reads `PREP.md` first.** If it exists: Decisions are copied verbatim (superpowers
  writing-plans' Global Constraints rule), **Not this** becomes §2.2, Discretion is decided silently,
  Assumptions land in §7.2 with their confidence, Verify seeds §6.1. Gap questions only for a category
  PREP.md left empty. The two guards at `SKILL.md:64` become conditional: ask negative-scope only when
  **Not this** is empty; quantify only adjectives PREP.md did not already quantify.
- **The prohibition is written in spec, not prep** (gsd, superpowers): *"Never re-ask a `D-NN`. If the
  spec needs to contradict one, write it as a `[NEEDS CLARIFICATION: conflicts with D-03]` marker."*
- **Reading load**: with PREP.md present, Phase 2 does not load `question-bank.md` at all — 278 lines
  saved per run before the redesign's own cuts land.

### 5.5 Mechanics (PRIMARY, code.claude.com docs re-fetched 2026-09-07)

| Need | Mechanism | Note |
|---|---|---|
| Manual-only | `disable-model-invocation: true` | also blocks preloading into subagents; the docs' own example pairs it with `allowed-tools` |
| The idea text | `$ARGUMENTS` / `argument-hint` | with no placeholder the harness appends `ARGUMENTS: <raw>` itself |
| Keep the conversation | **no** `context: fork` | fork = *"It won't have access to your conversation history"* — wrong for an interview; the raw research had this backwards |
| Hand the file forward | spec reads `.specs/<current>/PREP.md`; optionally `` !`cat …` `` injection | there is no skill-to-skill call; the file is the interface |
| Option-shaped turns | `AskUserQuestion` | free text still arrives via *Other*; `askUserQuestionTimeout` is a built-in "silence is acceptance" if ever wanted — **off by default** for prep |
| Stacking | `/flow:prep /flow:spec <idea>` loads both (≥ v2.1.199) | mechanically allowed, **do not document it** — spec must not start before PREP.md exists |
| Command surface | `commands/flow/prep.md` beside `spec.md`/`next.md` | `11-flow-redesign` §3.1: plugin.json declares skills only today; the frontmatter keys in use across all 27 SKILL.md files are `name`, `description`, `argument-hint` (2), `user-invocable` (1) |

### 5.6 What is deterministic, what is prose

| Rule | Enforced by |
|---|---|
| **Not this** non-empty, **Verify** non-empty, ≤3 **Open**, `Questions: n of 12` ≤ 12 | `flow lint` on PREP.md (same parser family as `TASKS.md`); `/flow:spec` refuses a PREP.md that fails it and prints the `fix:` |
| PREP.md written after every answer | the `Questions:` counter must match the number of `— user, Qn` receipts; a mismatch is a lint WARN |
| No `D-NN` re-asked by spec | prose in `/flow:spec` + spec-judge D7 citing `D-NN` IDs |
| One question per turn, explore-first, hypothesis-with-confidence | prose in prep (no hook can count questions in a turn cheaply) |
| Bounded route never writes `.specs/NNN/` | `11-flow-redesign` §3.6 route table; `Route:` line in PREP.md is the record |

## 6. Errata from the sweep — do not propagate

1. `context: fork` isolates; it does **not** inherit the parent conversation (that is the fork *subagent
   type* / `/subtask`, a different feature).
2. spec-kit's clarify taxonomy has **10** categories; "Terminology & Completion Signals" is not one of them.
3. gsd CONTEXT.md has **7** blocks and **no** frontmatter.
4. superpowers' ambiguity check reads *"Could any requirement be interpreted two different ways? If so,
   pick one and make it explicit."* The circulating "resolves interpretations…" quote is fabricated.
5. JTBD's HBR source has three authors (Christensen, Cook, **Hall**); the "18-hour observation" is not in it.
6. The gsd "Claude's Discretion" label and assumptions mode are SECONDARY; confirm in gsd-core before
   quoting them in a skill.

## 7. Recommendation

Build `/flow:prep` as **grill-me + a file + a budget + a route**, on the sibling worktree's redesign branch
once `/flow:spec` and `/flow:next` exist there:

1. `commands/flow/prep.md` (~60 lines): the nine rules in §5.3, `disable-model-invocation: true`,
   `argument-hint: "<idea>"`, writes `PREP.md` per §5.2 after every answer, ends with `Route:` and
   `Next: /flow:spec` (or the bounded design in chat).
2. `flow lint` learns PREP.md (four checks in §5.6).
3. `/flow:spec` gains the consumer clause in §5.4 and skips `question-bank.md` when PREP.md exists.
4. Retire nothing yet: `grill-me` stays as the stateless, repo-less tool (Pocock keeps the same split —
   grill-me / grill-with-docs / wayfinder).

Open rulings for the user: (a) recommend-with-question (hypothesis + confidence) versus grill-me's
recommend-after — this doc argues for the former; (b) whether `AskUserQuestion` is used for option-shaped
turns or every turn stays plain text; (c) whether prep lives in `.specs/NNN-slug/` before a spec number
exists, or in `.specs/prep/<slug>.md` and moves on `/flow:spec`.
