# 14 — How to build a bug-fix skill, and what `/flow:fix` gets wrong

What the field has converged on for agentic bug-fixing, and an audit of `/flow:fix` against it. Written 9 September 2026 from a 6-angle sweep (16 agents: 6 researchers, 6 independent fact-checkers, a 3-lens judge panel, a completeness critic). 77 findings, **0 fabricated**, every load-bearing claim re-verified by hand against the CLI source before it was written down here.

**Evidence grades.** **A** — source file or vendor doc read verbatim on 2026-09-09. **B** — arXiv/benchmark result with a reproducible method, re-fetched. **C** — single practitioner source, not re-verified. **X** — a claim the checkers killed (§8).

---

## 0. The one-paragraph version

`/flow:fix` has almost certainly never been executed end to end. Four independent blockers sit in five consecutive lines of its arming block, any one of which ends a run inside ninety seconds, and all four survived review because nobody has typed the command. That is the finding that reorders everything else: the right response to unexecuted code is not eighty edits, it is one real run. Underneath the four blockers is a single design omission — `/flow:fix` is written as one linear document but **executes across a session boundary**, and the handoff across that boundary was never specified. Five of the top ten defects are that one root cause wearing different hats. And underneath *that* sits a strategic question worth answering before any repair: the entire back half of `/flow:fix` is an untested reimplementation of `/flow:next`, which is tested.

## 1. The four blockers (A, all re-verified by hand)

`fix/SKILL.md:182-186`:

```bash
flow loop init "fix: <bug description>" --verify "$TEST_CMD" --shape fresh \
  --prompt-file .claude/loop/prompt.md --max-iterations <N>
```

| # | Blocker | Proof |
|---|---|---|
| 1 | `$TEST_CMD` is a **markdown field**, not an exported shell variable. It is defined at `shared/project-detection.md:77` as `- TEST_CMD: [value or ""]`. In a real shell it expands to empty. | `bin/lib/loop/init.js:146` → `flow loop init: --verify is required`, `return 1`. |
| 2 | `--prompt-file .claude/loop/prompt.md` is **cwd-relative** with no error handling, while every other loop path anchors at the git toplevel. | `init.js:115` — bare `fs.readFileSync(args.promptFile)`. Uncaught ENOENT from any subdirectory. |
| 3 | Step 2 (`SKILL.md:132-134`) permits "document exact steps to reproduce manually" **or** a failing test. Take the prose branch and the suite is green. | `init.js:151` → `verifier already passes; nothing to loop`, `return 1`. The skill itself notices this contradiction 50 lines later at `:188`. |
| 4 | The Post-Loop Check greps for `stopped: cap\|time\|budget\|stall\|wedge\|error`. `flow loop status` **never prints that string** — it prints `status:` and `stop_reason:` on separate lines. | `bin/lib/loop/status.js:36,40`. |

**Corroboration that it has never run.** There is no `test_fix*.sh` — the repo ships `test_next.sh`, `test_loop.sh`, `test_spec_prose.sh`, `test_prep_prose.sh`, `test_wave5_prose.sh` and 12 hook tests, and zero for `fix`. `test_wave5_prose.sh` scopes its banned-pattern sweep to `next/` only. No `workflow-state` or `fix-diagnosis` artefact appears anywhere in git history. And the author fixed 13 bugs in this repo (`git log --grep='^fix'`) — **none of them through `/flow:fix`**.

**A fifth, unpriced.** The arm block passes `--max-iterations` (up to 60 for a self-classified "complex" bug) and **no `--max-usd`, no `--max-minutes`**, though `loop/SKILL.md:27` names `--max-usd` as the fresh shape's cost mechanism. PROGRESS.md:22 records this repo's own headless probes at **$0.79 and $0.80 per iteration**. So `/flow:fix` on a "complex" bug arms an uncapped ≈$47 unattended run on a loop nobody has dogfooded. Eighty findings and nobody priced a run.

## 2. The root cause behind five of the top ten

`/flow:fix` is one document that runs in **two different processes**:

- `SKILL.md` Phase A is read by an interactive session with a user, plugin context, and `$ARGUMENTS`.
- `execution-prompt.md` is copied into `.claude/loop/prompt.md` and fed to fresh, amnesiac `claude -p` sessions with **no plugin context, no arguments, no transcript**.

Every defect below is that unspecified crossing:

| Symptom | The crossing it fails at |
|---|---|
| `$TEST_CMD` literal in a bash block | a markdown field cannot cross into a shell |
| `${CLAUDE_PLUGIN_ROOT}` shipped literally into `.claude/loop/prompt.md` (twice) | a plugin variable cannot cross into a session with no plugin |
| `--skip-verification` parsed at Step 0, never persisted | a flag cannot cross without being written down |
| `CURRENT_STEP` never advances past "Triage & classification" — a step `execution-prompt.md §4` has **no branch for** | nothing ever ticks the first three Progress items |
| Verification Step 4 blocks on a human question, inside a loop with no human | a gate cannot cross into an unattended process |

Do not file five tickets. **Specify the crossing once.**

## 3. How other people build these (A)

Named projects, files fetched this run.

**github/spec-kit** — `extensions/bug/`: three *separately invoked* commands (`bug.assess`, `bug.test`, `bug.fix`) sharing only a slug, each writing exactly one report into `.specify/bugs/<slug>/`. Position is recomputed from **which files exist**, never from a checklist the model ticks. Its README carries a real guardrail: *"`speckit.bug.assess` and `speckit.bug.test` **never modify source code** … `speckit.bug.fix` is the only command that edits source code."*

**obra/superpowers** — `verification-before-completion`: the regression-test proof is `Write → Run (pass) → **Revert fix** → Run (MUST FAIL) → Restore → Run (pass)`. And it refuses a difficulty axis outright: *"Simple issues have root causes too."*

**wshobson/agents** — `debugging-toolkit/smart-debug.md`: classification that *pays for itself* — it branches on which **tools** get used (interactive / observability-driven / time-travel / chaos / statistical), not on a difficulty number. Its `team-debugger.md` agent has **no Edit or Write tool at all**.

**SWE-agent** — gates submission behind a fixed review message that re-runs the reproduction **at submit time** and shows the agent its own diff while asking whether it touched tests.

Patterns in 3+ independent projects: **(a)** investigation is *structurally* unable to edit source, **(b)** each stage writes exactly one file and position is read from disk, **(c)** verdicts are graded (`applied | partial | not-applied`), never binary, **(d)** fetched issue bodies are marked untrusted input.

## 4. What actually raises fix rates (B)

| Technique | Measured | Does `/flow:fix` have it? |
|---|---|---|
| Execute the generated repro test, don't just write it | SWT-bench: 15.9% → **18.5%** | No — Step 2 allows prose instead |
| A **bug-specific** oracle on top of the suite | Agentless's largest single ablation: **+5.0pp**, 3× the gain from regression tests alone | No — verifier is the whole suite |
| Two-sided repro validation (red for the *reported* reason, green after) | Agentless: fewer than half of red-on-buggy tests go green on the correct fix | Only after the fix, never on the repro |
| Localize *before* scoping | every strong scaffold; file count is an **output** of localization | Backwards — classifies by file count first |
| Execution-derived localization over model-guessed | AutoCodeRover **+3pp** | No — Step 3 eyeballs `git log -10` where `git bisect run` is now free |
| **Parallel independent** repair samples, not serial retries | Agentless **+8 fixes** from *not* merging samples | No — three serial attempts, each inheriting the last one's wrong frame |
| Narrow reads | the only ablations where *adding* context **lowered** accuracy: −4.7pp localization, −5.3pp resolve | Constrains writes only, says nothing about reads |
| Post-edit lint + located-replacement edit format | SWE-agent +3.0; format 3× | **Already covered** by the harness — don't re-specify |

The single biggest miss: the loop's exit condition **never names the bug**. `--verify "$TEST_CMD"` is a *regression* signal. The discriminating check is the one test that was red because of this bug — and Agentless measures that difference at 3× the value of regressions alone.

## 5. Steal (ranked, with what it fixes)

| # | Steal | From | Cost |
|---|---|---|---|
| 1 | **Move Verification + PR out of the loop.** The loop owns Fix + regression test only. `$TEST_CMD` goes green at step 4 of 7, so `tick.js:113` sets `done` and terminates **before** the regression, verification and PR steps ever get an iteration — then `SKILL.md:199` tells the model to "report the PR URL" for a PR nothing created. | — (audit) | −15/+4 lines |
| 2 | **Commit the failing test *before* the fix.** This deletes the broken `git stash` proof at `execution-prompt.md:49` rather than repairing it (the fix is already committed at `:44`, so `git stash` either hides the test or stashes nothing), makes the loop's verifier *be* the reproduction, and matches how all 13 real fixes in this repo actually commit. | superpowers | one-line |
| 3 | **Bug-specific verifier**: `--verify "$REPRO_CMD && $TEST_CMD && $LINT_CMD"` with literal commands substituted from the diagnosis, plus `--max-usd`/`--max-minutes` and a `flow loop status` collision check before arming. Kills blockers 1, 4, 5. | Agentless | ~8 lines |
| 4 | **Position from disk, one artefact.** Delete `.claude/workflow-state.local.md` (a state file spec 004 abolished; `test_wave5_prose.sh:281` already forbids the string in `next/`). Ride-along: `shared/project-detection.md:38,61` hardcodes writing to the dead file. | spec-kit | −50 lines |
| 5 | **Read-only Phase A.** State it in one line and route diagnosis through the existing read-only `explorer` agents. flow already proved this at agent level (`agents/triage.md:4` has no Edit) and then didn't apply it to its own Phase A. | spec-kit, wshobson | one-line |
| 6 | **Untrusted-input rule for issue bodies.** `/flow:fix 143` pulls a third party's prose into a session `flow loop run` is about to hand `--permission-mode auto`. One paragraph in `shared/issue-refs.md` fixes `/flow:fix` and `/flow:issue` at once. | spec-kit, wshobson | one-section |
| 7 | **Graded verdicts** (`verified / partial / failed`) instead of a binary checklist. flow already has this vocabulary at the loop layer (`done/suspect/stopped/blocked`) and collapses it back to checkboxes in `fix`. Only `verified` may open a non-draft PR. | spec-kit | one-section |
| 8 | **Sibling-call-site field** in `diagnosis.md`: every caller of the changed function, `grep`ped not guessed. "Incomplete fixes" is the largest suspicious-patch category at 14.74% — a narrow test passes a patch that fixes only the reported path. | (B) | one-line |
| 9 | **`git bisect run`** on Step 2's minimal failing command, replacing Agent 2's `git log --oneline -10`. | AutoCodeRover | one-section |

| 11 | **`argument-hint`** in frontmatter (five siblings have one), and a **description rewrite**: cut the "Classifies bugs…" internals and the raw `Trigger keywords:` dump — the two things Anthropic's own description optimizer says not to write — and spend the words on sibling boundaries instead. Every sibling names `/flow:fix` in its negative boundary; `fix` names none of them back. | Anthropic docs | one-line |

## 6. Do NOT take

| Don't | Why |
|---|---|
| **Self-rated complexity** (`Simple/Medium/Complex` by file count) | No researched project does this. It is the least-informed estimate anyone will make about this bug, it buys an iteration budget the loop's own caps already bound, and it spends a **user turn** on a question the user cannot answer. Keep the *category* axis — that one gates loading the browser reference, which is a real token cost. |
| **Human gates with a safe default** | `/flow:fix` stops the user twice before a line of code is written. `/flow:spec` forbids this by name: a gate whose answer is always "yes" trains the user to rubber-stamp, spending the credibility of the one gate that matters (the diagnosis). |
| **A `.claude/fix/<slug>/` stage-file directory** | The spec-kit shape is right in instinct, wrong in size here: it would be a *second* state system beside `.claude/loop/loop.md`, still invisible to `flow next`. Delete the state system; don't rebuild it in a new shape. |
| **Parallel repair inside a loop iteration** | The literature is right that parallel samples beat serial retries — but three subagents on three branches inside a fresh `claude -p` whose driver runs `git add -A` at every tick (`driver.js:107-111`) is how you lose work. Fan out in the **main session**, like `next`'s Building step does. |
| **A self-editable verifier script** | The top-scored finding proposed `.claude/loop/verify-fix.sh`. `tamper.js:103` cksums the *contract string*, not the file it invokes, and `CHECKPOINT_EXCLUDES` doesn't list it — so the model could edit its own verifier and the driver would commit the edit. Violates `loop/SKILL.md:38` outright — *"It must be able to go green by editing source, not by editing the check."* **Take its alternative clause instead** (steal #1). |
| **Trimming the NEVER list** | Two agents pushed this. `fix` has 10 bullets against `next`'s 13 and `spec`'s 9 — it is not an outlier, and one proposed cut would have deleted `NEVER fix without reproducing`, the skill's load-bearing rule. |
| **Stripping the MANDATORY banners from `fix` alone** | `spec/SKILL.md:50` uses the identical banner. If it is cargo cult (no published measurement supports ALL-CAPS emphasis), that needs a plugin-wide ruling, not a one-skill divergence. The structural fix — flatten the reference chain so partial reads can't happen — is the real remedy anyway. |
| **Adding an `evals/` directory** | Scored 28/100. Two external script runs to tune one description string in a personal plugin, for a problem never observed. |
| **Splitting the 207-line SKILL.md** | It is under the cap and progressive disclosure is fine. The problem is not length, it is that the extra ~100 lines over its siblings are the ones that are wrong. Cutting the dead ones gets to ~110 for free. |

**Defended — do not simplify away.** The `flow loop` routing with a verifier the model cannot edit is the best thing in the skill: it converts "NEVER fix without reproducing" from prose into a precondition the harness checks (arming *fails* if the repro isn't red). The single `triage` subagent earns its keep. So does the explicit **do-not-load** rule for the browser reference — a load trigger with no matching skip trigger loads everything.

## 7. The strategic question: repair, or merge?

The critic's argument, and it is strong:

**For merging the back half into `/flow:next`.** The README says there are two doors. `router.js` has **no `fix` state** — verified. Everything in Phase B already exists next door *and is tested*: branch, gates, `flow check --fix`, the review ladder, `PASS-<sha>.md`, the human verification gate, `gh pr create --draft` → `gh pr ready`, `flow tick`, the `Next:` line. `/flow:next` has `test_next.sh` plus ~40 assertions; `/flow:fix` has zero tests. The genuinely unique content of `/flow:fix` is Phase A — triage, reproduce, root cause. About 60 lines. Everything else is a second, untested, unrouted reimplementation of the build pipeline. Roughly 35 of the 77 findings evaporate because the machinery they critique is deleted rather than repaired.

**Against.** A bug's blast radius is **discovered, not specified**. `/flow:spec` computes its route from footprint known up front; you cannot know a bug's footprint before reproducing it. And `next`'s per-task RED/GREEN writes a test *from a spec* — a different object from a test that pins an **observed wrong value** from a real error string. The reproduce-before-fix guarantee has no home in `next` today.

**The synthesis:** `/flow:fix` becomes ~50 lines and ends at the spec boundary — triage → reproduce into a committed failing test → diagnose → write the one-phase `TASKS.md` whose single `verify:` **is** that test → `flow use` → `Next: /flow:next`. Reproduce-first survives as the precondition for writing `TASKS.md` at all. The two-door invariant holds. The router sees it. The back half is inherited already-tested. What is lost is the unattended fresh-loop path for bugs, which has never run and which `/flow:loop` still offers by name.

**This decision comes first**, because under the merge, steals #1 and #3 are wasted work — they repair the loop path that merging deletes. Only #4 (one artefact, position from disk) is correct in both worlds.

## 8. Killed and corrected (X)

The fact-checkers and judges killed four claims before they reached this document:

- **"`shared/issue-refs.md` is untracked."** False — `git ls-files --error-unmatch` returns it. The finding was derived from a stale git-status snapshot, not from the repo.
- **"`agent-browser-reference.md` is stale, migrated to `claude-in-chrome-reference.md`."** False — the file exists and nothing migrated away from it. Only the missing `${CLAUDE_PLUGIN_ROOT}` prefix on that reference is a real defect.
- **"Freeze `SKILL.md:170-207`; the loop spine is already right."** Rejected by all three judges: that exact range holds three of the four confirmed blockers. The spine is right; those lines are not.
- **"The Progress checklist is a strength other flow skills should adopt."** Rejected — nothing ever ticks its first three items, so `CURRENT_STEP` hangs on a step the execution prompt has no branch for. Adopting it would spread the abolished state system across the plugin.

Also corrected: `complexity-self-classification-earns-nothing` overstated "every project" (spec-kit does classify — by *severity*, and it buys no budget); the regression-test finding was mislabelled `AVOID` when its content is the single best correctness fix in the set.
