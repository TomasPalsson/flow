# Step 6 — PR

Push, open a **draft** PR, then promote to ready only after re-verifying every gate live.

```bash
git push -u origin $(git branch --show-current)
```

```bash
gh pr create --draft --title "<type>(<scope>): <desc>" --body "$(cat .claude/pr-description.md)"
```

Two facts are two calls: **never chain shell commands** with `;`, `&&`, `||` or `|` here — a chained command matches no pre-approval and parks a walk-away run on a permission prompt.

## Description

Build `.claude/pr-description.md` from `git log <base>..HEAD` (it should show Red → Green → Refactor), the plan's "Why", the review findings kept at ≥80, `.claude/verification/*.md`, and the QA report — with a verdict table.

The body must also name **what did NOT run and why**: components skipped by the value litmus, a size tier that skipped E2E, a scaled-down QA pass, a judge that was not requested. A reader who knows what was not checked can calibrate the table; one who does not reads PASS as complete. List every `Assumption` and every parked review ruling.

## Promote

Before `gh pr ready`: run `TEST_CMD`, `LINT_CMD` and `TYPECHECK_CMD` **now**, confirm every review verdict is clean, browser assertions PASS, the user approved, QA PASS, and no `[VERIFY]` strings remain. **Never promote with a failing gate.**

Then clean up: `.claude/*.local.md`, `.claude/flow.json`, `.claude/pr-description.md`, `.claude/slices/`, `.claude/review/`, `.claude/verification/`, `.qa-report/`.

## Unattended

- **Never run `gh pr ready`.** User approval is one of its preconditions and by definition has not happened; a ready PR with no human verification looks reviewed and is not.
- Do **not** delete `.claude/verification/` or `.claude/review/` — the user needs that evidence at PR review.
- Add an "Unattended run" section listing every auto-resolved decision, every Assumption, and every deferred or skipped gate.

## After the PR

Architecture deepening is **not** part of this pipeline. Offer it as a separate run — never assume it — and stop:

> *"Shipped. The build touched `<modules>` and may have left shallow seams. `/flow-deepen` runs a behavior-preserving architecture pass over the merged diffs — characterization-test-first, emitted as new slices. Run it, or stop here?"*

`--unattended` skips this offer entirely and says so in the PR body. Nothing is emitted without the user's explicit approval, and **never emit a deepening slice that changes an interface, external contract, or caller-visible symbol without the user's explicit decision** — that is a feature choice wearing a refactor's clothes.

End the step with the line `Next: …` from `flow next`.
